# vox-type：预铸语音资产层 + 双工行为控制器

一句话：把语音链路里**流程写死**的那几句话术提前铸成音频，轮到它时直接播，不等模型现场生成；
不确定的部分才动用模型。命中一次是磁盘读，不是一次合成。

## 1. 什么时候该用它 / 不该用它

**该用**：做客服 / 催收 / 政务 IVR 这类语音 Agent，首响被 TTS 合成卡住，
**且有一部分话术是流程写死的**——问候、转人工、报修确认、告别。那部分话术给它。

**不该用**：全是自由对话的系统。用户每次说得都不一样、必须现想的（投诉解释、个性化答复）
不是它的输入面——那些还是交给模型。这类系统装上只会拿到一串未命中。

- 该用它：「报修确认后播报『工单已受理，师傅两小时内上门』」。句子固定，铸一次，
  之后每次接通都是磁盘读。
- 不该用它：「用户投诉物流慢，生成一段安抚话术」。输出依赖上下文，铸不出来，
  走 LLM 加现场 TTS。

（口径出自仓根 `README.md` 的「你什么时候需要它」）

## 2. 三条接入路径怎么选

| 场景 | 走哪条 | 理由 |
|---|---|---|
| 脚本 / cron / CI 里播报或验证 | **CLI** | 零常驻、退出码可判、调试透明 |
| agent 在对话里查「铸了没有 / 这批 key 哪些没铸 / 包还合规吗」 | **MCP** | 工具面生态，覆盖面最大 |
| 语音框架 / 业务系统里要真正出音 | **进程内嵌入** | 毫秒级首音只在这条路上兑现 |

代价一并记住：CLI 每轮起一个 Python 进程（数十毫秒启动开销），且宿主必须与 vox-type 同机；
进程内嵌入绑 Python，要自己处理仓库根的 import 路径。

本仓是**前置包**，不依附任何框架，没有 `pyproject.toml` 也没有 `requirements.txt`，**不能 pip install**。
没有第三方依赖。跨进程要用 `PYTHONPATH` 指向仓库根，或直接用 `bin/vox`（它按脚本自身位置推导仓库根）。

三条路径的完整命令、期望输出与期望退出码在 `docs/25`，每节都是可直接复制的真命令。
想看最小可跑 demo，进程内那条在 `examples/embed_demo/`。

## 3. 命中与未命中的语义（最容易含糊，先说清）

- **命中 = 磁盘读，零 TTS 调用。** 全命中且无槽位时 `tts_calls=0`——一次合成都没发生。
  仓内自证包的四单元全命中就是 `hit=4 miss=0 fallback=0 tts_calls=0`。
- **未命中 = 默认 fail-closed 中止，退出码 5**，stderr 一行中性说明「已按 fail-closed 中止」。
  这是预期内的业务结论，不是崩溃。
- 降级到宿主原 TTS **必须显式**传 `--allow-fallback`（进程内是 `allow_fallback=True`），
  并且降级**留痕**：结果里带 `fallback_count`，计数不丢。
- **降级只能显式声明，不能默认发生。** 本仓纪律 4 禁止静默降级：
  语音链路的静默降级表现为「突然换了个声音」，事后无法定位。

两道闸会提前拦住你，不是 bug：

- **引擎一致性闸**在任何包内查表之前比对包清单的 `voice` / `model_version` 与 adapter。
  身份不等就是 `engine_mismatch` → fail-closed 中止，且不写输出文件。
  所以 CLI 的 `--adapter` 不能省：`tts_calls=0` 意味着没合成，但身份校验照跑。
- 进程内嵌入有一个同名目录坑：你的项目里只要有 `adapters/` `core/` `assets/` `tools/` `cli/`
  中任一同名目录，vox-type 的同名顶层包会被静默劫持，而失败信息不指向真因。
  `examples/embed_demo/demo.py` 因此在任何产品模块 import 之前先判一次落点，撞名就退出码 2 并指出真因。

退出码口径见 `docs/08`：`0` 成功 / `2` 用法或参数错误 / `3` 运行期失败 / `4` 质检不通过 / `5` fail-closed 中止。

## 4. 铁律：MCP 与 CLI 是控制面，不出音

三个 MCP 工具的出参里**刻意没有 `wav_path`、没有 path 字段、没有音频字节**。
拿到 `hit: true` 只说明「这句在包里是铸好的」，不等于拿到了声音。

为什么不让 MCP 出音：多一跳网络加多一次工具往返，会把命中即播的毫秒级首音稀释成「又一个 TTS」。
要真正听见声音，宿主自己走进程内 adapter（第 2 节第三条路）。

一句话记住：**控制面（CLI + Skill + MCP）决定说什么、查什么；数据面（出音）是进程内 adapter / 常驻服务。**

## 5. 上手三步

```sh
git clone https://github.com/starmcainiao/vox-type && cd vox-type
sh examples/selftest.sh      # 环境自检 → 串真命令 → 期望值 vs 实际值 → 末行 SELFTEST: PASS|PARTIAL|FAIL
```

第三步：读 `docs/25`，按你的场景选接入路径。

想先听见声音再决定：`README.md` 有一节「30 秒，零引擎」，clone 完直接播预铸好的自证包，
端点离线也能跑，全程一次合成都没发生。

> 首响毫秒数会随机器与冷热缓存漂移，别把它当稳定指标引用；要引用数字，
> 取 `eval/` 里固定语料加固定种子的可复现报告，并标清统计口径。
