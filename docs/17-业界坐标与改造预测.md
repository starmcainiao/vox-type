# 17 · 业界坐标与改造预测（2026-09 网络探测）

> **性质**：前瞻设计。承接 `docs/16`（痛点验证）之后的「后来发展预测与改造方向」。
> 探测三路：semantic caching 生产教训 / constrained decoding 工程形态 / 语音链路缓存分层。
> **一句话结论**：业界正在用多层缓存 + 约束解码解决我们手工解决的问题——我们的预铸层
> 在业界分类学里是「audio phrase cache 的治理化极致」（业界 phrase cache 命中率 30–60%，
> 与本仓 23% 流程话轮口径互证）；**下一跳的正解不是更聪明的检索，而是「约束解码」——
> 用 Trie/FSM 把 LLM 输出空间物理约束到合法 key 集合**（这正是「树机制」直觉的业界正解形态）。

---

## 一、三个业界坐标

### 坐标 1：Semantic caching 的生产教训——反证咱们的精确口径

- 业界形态：GPTCache（引 257 次）开山，Redis 等跟进；生产阈值普遍 **0.85–0.95 余弦**；
- **教训（原文级）**：「盲目接受最近邻会返回错误条目，仅靠阈值不是充分保障」（HuggingFace 实战帖）；
  「相似度阈值是 semantic caching 最关键也最没有统一答案的配置」（tianpan.co 2026-04）；
  GPTCache 原作者自认「调阈值 = 在 hit-rate 与 false-positive 之间走钢丝，需进一步研究」。
- **对本仓的含义**：咱们场景（客服话术 + 合规）假阳性的代价是**播出错误话术**——业界踩的坑
  正是 `docs/10 §10.2 裁定 1`（逐字相等是唯一被允许的判定）预先堵死的。**业界教训是咱们裁定
  的外部佐证：不是我们保守，是场景不容忍**。可借鉴的只有「分级命中」的**形态**
  （exact → 严格验证的近似 → miss），且近似档只能做诊断提示（见 §三），永不进命中。

### 坐标 2：Constrained decoding——「树机制」直觉的业界正解

- 业界标准形态：**Trie 前缀树 + FSM 编译 + token 级掩码**（XGrammar，MLC 2024；Outlines；
  2025 arXiv 综述称 constrained decoding 已是结构化输出的主导技术）——在解码期把 LLM 的
  每个 token 采样限制在合法文法内，**schema 违规在物理上不可能发生**，消灭 validate-retry 循环。
- **对本仓的含义**：这正是「让 brain 按 key 说话」的**下一跳正解**。当前路线（docs/15 方案 A′
  话术同源）靠「brain 碰巧说包里的话」；升级路线 = 把 `heat_kefu` 的 40 key 集合编译成 FSM，
  brain 的 LLM 引擎（vLLM + XGrammar / Outlines）**只能在合法 key 空间里采样**——
  命中率从「同源碰上（真链路实测 2/2）」升级为「解码器保证（结构性 100%）」，
  钩子的 key 档直通（T30 已交付）现成接住。**用户「树机制」的直觉在这里完全成立——
  只不过树长在解码器里，不是长在检索里。**

### 坐标 3：缓存分层全景——预铸层在业界分类学里的位置

2026 年语音 Agent 的标准缓存栈（由深到浅）：

| 层 | 省什么 | 业界数据 | 本仓对应 |
|---|---|---|---|
| KV cache（单次生成内） | 生成内重复计算 | 语音链路 7–8 轮后 prefill 重算退化的已知问题 | —（命中路径无模型） |
| Prompt caching（跨请求前缀复用） | token 费 41–80%、TTFT −13–31% | arXiv 2026-01 评估 | — |
| **Audio phrase cache（预铸音频）** | **100–350 ms/命中** | **phrase cache 命中率 30–60%** | **本仓预铸层 = 此层的治理化极致**（准入/质检/指纹/重铸），0.232 ms 比业界省的 100–350ms 又低 3 个量级 |
| ↑ 云端对照（本仓自测） | 全云栈未命中链 P50 ≈ 2.87 s | 阿里百炼 qwen-turbo TTFT 226ms + qwen-tts 合成 2.45s；命中 0.1ms（28700×） | `labs/cloud-bench/`（2026-09-21，跨厂商实证：命中路径与引擎无关） |
| Semantic response cache | 生成费 | 阈值 0.85–0.95、假阳性之痛 | **明确不做**（见 §三） |

业界 phrase cache 命中率 30–60% ↔ 本仓流程话轮 23%（真实催收语料实测）——**互相印证**：
固定话术占通话的 1/4 到 1/2，这部分被业界公认值得缓存，而**只有本仓给它配了治理**。

## 二、改造预测（按时间线）

### 近期（brain 侧升级时一并做，未开卡）

**T 未来·key 约束解码**：kefu brain 的 LLM 引擎若迁移到支持 guided decoding 的运行时
（vLLM + XGrammar / SGLang / Outlines），把 `packs/heat_kefu` 的合法 key 集合编译为 FSM/文法，
约束 brain 输出 `{"key": "..."}` 形态——非法 key 采样概率为 0。**这是「brain 按 key 说话」的完全体**，
且与方案 A′ 叠加（同源保内容，约束保格式）。

> **✅ 勘察已完成（2026-09-21，`labs/guided-decoding/`）**：当前 kefu 的 LLM 运行时（商汤 OpenAI 兼容端点，
`sensenova-6.8-flash-lite`）**不支持物理约束**——`json_schema`（strict）**明确 400 拒绝**、
`guided_json` **被静默忽略**（判决测试：把 enum 设成模型绝不会自然输出的值，返回 200 但输出是自由文本）。
→ 这条路线**必须换运行时**才能落地。当前可用档只有 `json_object`（保证"是 JSON"、**不保证 key 合法**）
→ **无论走哪条路，输出侧必须显式校验**（`key ∈ 包内 key 集合`），不得依赖运行时保证
（`guided_json` 的"200 + 无效果"正是本仓红线里的静默降级形态）。
该端点升级或换模型时**重跑一条命令即可复核**（复现命令见该目录 README）。

### 中期（冻结区开批时）

1. ~~**14 条多分句「整段 → plan 拼接匹配」**~~ ✅ **已落地（T33，2026-09-21）——且不必开冻结区**：
   业界 response templating + slot filling 的成熟形态；实际落地 = **拆句铸入**（`<源 key>__<句序>`，
   `docs/06 §6.1.4`「长话术一律拆 key」的既定形态）+ 查询面**逐字覆盖序列命中**
   （`find_hit_sequence`，`docs/10 §10.7`：最长优先、任一段不中即整体未命中、不播半句）→
   交给 `runtime.Executor` 播多 unit plan（执行器能力本来就在）。实测（`labs/heat-kefu-seq/`）：
   14/14 整段命中、命中臂拼接 **P50 ≈ 5 ms**（冷缓存首跑 ~22 ms）vs 慢路 `say` **≈ 575 ms**、`tts_calls = 0`。
   **下一步**：把序列档接进 kefu 钩子（多段拼接 + 音色一致性）= 跨仓卡；
2. **诊断性 near-miss**（BK-树/Trie 编辑距离检索）：未命中报错时附带最接近的合法 key——
   **只进报错与留痕，永不进命中**（`docs/10 §10.2 裁定 1` 红线不动）。

### 远期（S2S / 端侧时代）

- S2S 黑盒化 → 「固定话术不经过模型」的白盒资产层价值凸显（docs/16 §三的逆向机会）；
- **端侧友好性**：预铸音频零推理、约 1 MB/分钟存储（业界口径）——oMLX 已在本机跑 ASR/TTS，
  预铸包是天然的端侧/边缘资产，随 S2S 端侧化趋势一起下沉。

### 重审触发器（不建基建，只留入口）

语义路线若要重审：**条件 = embedding 模型代际跃迁**（非调参）。重测成本已压到 1 分钟
（`labs/corpus-harvest/README.md §十` 对账表：一条命令跑 semantic_probe）。
**在触发器到来前，不为 11.8% 的路线建任何向量索引基建。**

## 三、不做什么（边界，与业界教训对齐）

| 不做 | 理由 |
|---|---|
| 阈值式 semantic caching（0.85–0.95 余弦近邻进命中） | 业界假阳性教训 + `docs/10 §10.2 裁定 1`（自造命中红线）；合规场景错一句话的代价 ≠ 聊天场景 |
| 为语义检索建向量索引（HNSW/IVF） | 路线 accuracy 已否（11.8%），速度不是瓶颈；留重审触发器即可 |
| 把近似匹配放进命中判定（哪怕 1 字编辑距离） | 红线；near-miss 只许进诊断输出 |
