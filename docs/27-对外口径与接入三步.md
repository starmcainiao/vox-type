# 27 · 对外口径与接入三步（草案）

> **本文回答三件事**：它是什么（一句话怎么说）、接缝在哪（切进语音链路的哪一格）、
> 用户要做什么（填什么、填完之后会发生什么）。
> **状态**：草案，待维护者过目改口径。**文中所有数字都有出处**（`labs/` 的实测报告或本次实地测试），
> 未实测的一律不写。

---

## 一、一句话（按场合分三个版本）

| 场合 | 说法 |
|---|---|
| **给开发者（是什么）** | 把语音 Agent 里**流程已经决定要说的话**提前铸成音频资产；轮到说的时候直接取，不合成。 |
| **给框架作者（切入点）** | 它是 **LLM 与 TTS 之间的一个可选接缝**：给它「这一段要说什么」（key + 槽位），它还你一段 16 kHz 音频 + 一条事件。 |
| **给业务方（省什么）** | 用**存储**换三样东西：**时间**（首响毫秒级 vs 数百毫秒）、**成本**（命中即零合成调用）、**确定性**（说的每一句都能读、能改、能拒、能版本化）。 |

**一句话总结**：**「用存储换计算」是对的，但换到的不止计算——还有确定性和可审核性。**

---

## 二、切进链路的哪一格

```
用户说话 → [ASR] → 文本 → [LLM / 状态机] → 「这一轮要说什么」 → [TTS] → 音频 → 播
                                              ↑
                              ★ 前置包坐在 LLM 与 TTS 之间这个接缝
                                给 key + 槽位，还一段 16 kHz 音频
```

- **级联链路**（ASR→LLM→TTS）：它是 **TTS 前面的一道快路**——命中就不进 TTS。
- **端到端模型**（S2S）：没有中段接缝，只能做**轮级旁路**。

### 它省的是哪一段（**必须说准，否则会吹过头**）

> **不是**"模型说完话我们配音"，**而是**"当这一步的话由流程决定时，模型不必生成那句话"。

为什么必须这么说：如果由模型自由措辞，每次说法都不同，**按文本逐字查表的命中率实测是 0.00%**
（2433 条真实客服语料，`docs/11 §11.9.4`）。能命中的前提是**这一轮该说什么由流程给定的 key 决定**。

**诚实边界**：真实客服语料里，**流程决定性话轮占 23.0%**（1855 通 / 25810 话轮实测，`docs/12 §12.4`）。
对外只能说"**让流程决定的那部分话轮零合成**"，不能说"省掉 TTS 阶段"。

## 三、接入三步（用户要填什么）

> **一个业务一个目录，零内核改动。** 三份文件 + 一个决定：

| # | 用户要决定/填的 | 填在哪里 | 说明 |
|---|---|---|---|
| **1** | **选什么人物**：音色 + 引擎 | `pack.json` 的 `voice` / `model_version` | ⚠️ **必须与实际用来铸包的 `--adapter` 一致**（见下「两个必须写死的坑」） |
| **2** | **确定什么业务方向** | 新建 `packs/<业务>/` | 并过 `docs/14` 的**预铸准入判据**：只准流程决定的话轮（问候 / 确认身份 / 播报类 / 告别），禁从用户话术反推 key |
| **3** | **提供什么语句** | `phrases.json`（话术表）+ `script.json`（剧本）+ `trigger.json`（状态→plan 映射） | 一句话一条 variant；长话术拆 key；槽值不预先铸、运行时合成 |

**填完之后跑一条命令**：

```sh
sh bin/vox pack build packs/<你的业务> --adapter <与你填的引擎身份一致的适配器> --out /tmp/<业务>-pack
# → 得到一个资产包目录：manifest.json + audio/*.wav（16 kHz / 单声道 / 16-bit）
```

**校验它**：

```sh
sh bin/vox pack check packs/<你的业务>     # 只校验不预铸
sh bin/vox verify /tmp/<你的业务>-pack      # 对产物跑质检
```

## 四、填完之后会发生什么（"自动填充并返回"要说准）

宿主给一段 plan，回来的是一段音频。**但这里有两个"自动"要分清**：

| 机制 | 是什么 | 自动程度 |
|---|---|---|
| **key 命中** | 整句从磁盘读音频 | **完全自动**（实测首音 0.56–1.99 ms，零 TTS 调用） |
| **槽位填充** | `您的工单 {ticket_id} 已受理` 里的变量**运行时现场合成**后再拼 | 自动，但**这一段要过一次 TTS**（因为值不可枚举） |

**并且有一条红线要说在前面**：

> **「该说哪一个 key」不是这一层决定的。** 本层**不猜"该说什么"**——输入必须是宿主（业务状态机 / 编排层 /
  可选的 `trigger/`）给出的 `key + 槽位`。

所以"我填好之后它就自动"这句话要加一个前提：
**宿主要能回答"这一轮走到哪一步"**，并把它表示成一个 key。这一步不做，包再全也不会自动。

## 五、两个必须写死的坑（都是实测踩出来的）

### 坑 1 · 引擎身份必须与铸包用的适配器一致

`pack build` 目前**不校验**这件事，manifest 会**照抄包源声明的身份**。
实测（2026-10-12）：包源声明 `say`、却用模型适配器铸包 → 铸得出（rc=0、69/69 clean），
但 `run` 立刻 **rc=5 `engine_mismatch`**，播不出来。

**对外文档必须写死一句**：

> **你填的 `voice` / `model_version`，必须与你实际用来 `pack build` 的 `--adapter` 身份一致。**
> 不一致时，包铸得出来但播不出来（`engine_mismatch`，fail-closed）。

### 坑 2 · 只改话术要改**源码**，不是改产物

`packs/<业务>/*.json` 是**源码**，`manifest.json` 与音频是**编译产物**。
改话术 = 改源码 + 重铸 → 天然带 diff / 版本 / 回滚 / 灰度。
**不要手改 manifest 或音频**（很多包在 `PROVENANCE.md` 里明确写了"不得手改"）。

## 六、怎么判断值不值得接（选型判据）

**适合**：话术的一部分**由流程写死**（问候、转人工、报修确认、合规提示、告别），
且**首响被 TTS 卡住**、或**话术有合规/审计要求**。

**不适合**：全是自由对话（用户每次说的都不一样、必须现想的话）——那部分永远交给模型。

**一句话判据**：**你能不能列出"这一轮走到哪一步"？** 能 → 适合；不能 → 先别接。

## 七、对外不该再说的三句话（本次讨论的结论）

| ❌ 不该说 | ✅ 应该怎么说 |
|---|---|
| "省掉 TTS 生成阶段" | "让**流程决定的那部分**话轮零合成"（占真实客服语料 23.0%） |
| "帮你把语音缓存起来" | "按**状态**寻址的声音资产"（按内容寻址的缓存路线实测命中 0.00%） |
| "它会自动知道该说什么" | "**你告诉它这一轮要说什么（key），它立刻还你音频**" |
