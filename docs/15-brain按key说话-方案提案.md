## 一、发现与推论（证据）

| 事实 | 出处 |
|---|---|
| 流程话术 = yaml 逐字取用（`realtime_ask` / `faq_empty` / `pay_ask_user_no` …） | `kefu organs/客服/brain/blackiron_kefu_brain/misc_flow.py:84,91,94-96,117,128` |
| 带槽话术文本填充（`{building}{house}{roomTemp}{time}` → `.format()`） | 同上 :96 |
| 闲聊/FAQ 走 LLM（`gather`） | 同上 :55 |
| T11 的 text 档 0% 命中的真因：kefu 话术表与 vox-type 包**不同源**（两边各自写话术） | 推论，被上三行支持 |
| kefu 状态机话术 ≈ vox-type `docs/14` 的 A1/A2 准入类型（流程决定/状态播报） | 形态对照 |

**推论**：把 yaml 里**无槽固定句**按原文铸进包（key 对齐 yaml 键名），钩子文本档命中率
在「流程轮」上应直接接近 100%；带槽句按 `docs/14` B2（禁占位符）**不铸**——天然走原路；
闲聊/FAQ 轮不命中——这三类轮的实时分布本身就是有价值的实测数字（状态机轮 vs LLM 轮占比）。

## 三、方案 A′ 的形态与风险

**包内容**：yaml 中无槽、无 PII 的固定句（opening / transfer_ready / options / farewell /
fallback_route / pay_* / repair_ask.* …），key 直接用 yaml 键名（`opening`、`pay_ask_user_no`…），
加 `admission.md` 申报（A1/A2 类别 + yaml 出处）——正好是 `docs/14` 申报制的第一个真实用户。

**风险与防护**：

| 风险 | 防护 |
|---|---|
| kefu 话术进 vox-type（**公开预备仓**） | 待拍板①：话术是自造业务 demo 文案，无录音/会话/内网地址/token（已勘察 yaml 全文）；但「私域 → 公开预备仓」的内容流动本身要用户点头。保守选项：先落 `labs/`（不入公开分发）实测，验收后再定是否升 packs/ |
| brain 输出与包内 variant 有空格/标点微差（运行时拼接/控制台改动） | 钩子文本档用四步归一化（去空白/全半角/NFKC/小写）已覆盖大半；铸包前逐句与 yaml diff，差一个字符都不铸（保「逐字同源」） |
| yaml 是「配置控制台管理」的活文件（会变） | 铸包时记录 yaml 的 sha256 进 admission.md；yaml 变更 → 指纹不符自动不命中（走原路，fail-closed 天然成立） |
| 真链路实测要起 kefu 服务（brain 8092 / 语音端 8096） | 待拍板②：起停命令在 `docs/09 §10.4`，用后即关（第九批同款纪律） |
