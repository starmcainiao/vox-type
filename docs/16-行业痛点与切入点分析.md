# 16 · 行业痛点与切入点分析（2026-09 网络探测 + 实测对照）

> **性质**：战略验证。基于 2026-09-19 的网络探测（六路搜索：延迟指标 / 平台格局 / S2S vs 级联 /
> 成本经济学 / 缓存手法 / 中文合规市场）+ 本仓全部实测数字。引用来源见文末。
> **一句话结论**：痛点真实、市场在涨、切入点成立——但**主打叙事应从「零延迟零成本」重排为
> 「合规可审核的预铸话术资产层」**，延迟与成本是附带收益；最大的护城河不是缓存手法（行业皆知），
> 而是准入/质检/指纹/实测边界的**工程体系**与中文合规场景。

---

## 一、行业痛点四条（按证据强度排序）

### P1 延迟——真实，且是行业公认头号指标 ✓

- 行业共识：`time-to-first-token` 与 TTS 首字节是语音 Agent 的关键指标；优化目标 sub-second
  （~250ms 首 token + 75–300ms TTS 首字节即算「优化栈」）（AssemblyAI 2026-07、Cresta 2025-10）；
  LiveKit 社区仍有「3 秒停顿」的真实排障帖（2026-03）。
- **本仓对照**：kefu 真链路实测 LLM 首 token 4.19 s、Breeze TTS 42.3 s 超时（docs/09）——
  真实系统的痛比行业文章写的更重；我方预铸命中快路 0.232 ms（≈ 同引擎 2530×）。
- **诚实限制**：streaming 方案已把首响压进 sub-second——预铸的**边际**延迟价值集中在
  「高频固定话术」场景（流程入口/催收/通知/查询），不在开放式对话（docs/11 的 23% 边界）。
- **云端自测补全（2026-09-21，`labs/cloud-bench/`）**：阿里百炼 qwen-turbo TTFT P50 **226 ms**
  （自测证实行业「优化栈 ~250ms」）；qwen-tts 非流式合成 P50 **2.45 s**（生成回复 3.25 s）——
  **全云栈下 TTS 整句合成仍是秒级**，预铸命中（0.1 ms）把这一段整体归零：云端未命中链 P50 ≈ **2.87 s**
  vs 命中 0.1 ms ≈ **28700×**（口径见该目录 README：非流式为上界）。

### P2 成本——经济性成立，但单项 TTS 在降价，纯成本主张会稀释 △

- 语音 AI 全链 $0.10–0.45/min（企业常见），对比真人坐席 $1–3/min——AI 替人经济性成立；
  TTS 单项约 $0.05–0.08/min（ElevenLabs Scale），且厂商在持续降价。
- **本仓对照**：预铸命中的合成成本 = 0（一次性预铸）；但「省下的 TTS 钱」随 TTS 降价被稀释。
- **重估**：成本主张的真实价值在**私有化/国产化/高并发固定话术**场景（推理资源是硬预算），
  以及**确定性吞吐**（固定话术不占 LLM 并发）——不是「每分钟省几分钱」。

### P3 合规——中国侧最硬的痛点，且在收紧 ✓✓（主打叙事的靶心）

- AI 骚扰电话投诉 2024 年同比 **+230%**（黑猫投诉）；工信部 2024 拦截诈骗电话 15.3 亿次；
  厂商的应对是「内置 **500 余套合规话术模板** + 敏感词屏蔽」——话术治理已是刚需；
  金融/电商/政务贡献 72% 需求，全部是强合规行业。
- **本仓对照**：这正是本仓工程体系打中的位置——**准入判据**（docs/14，A1/A2 + 禁四类）、
  **四属性校验**（全 key 可达/无未审核文本）、**admission.md 申报制**、**yaml 指纹门禁**
  （话术一变钩子自动不命中）、**实测边界**（23% 流程话轮，不自造命中）——
  行业的「话术模板库」是静态配置，本仓是**有准入、有质检、有指纹、可审计的资产层**。

### P4 工程化缺口——cache 手法行业皆知，「资产层」无人做 ✓

- 「缓存预合成音频、命中即播」已是公开手法：**Vapi 官方文档**把 audio caching 列为延迟优化技术，
  hamming.ai 给出「每分钟缓存音频约 1MB 存储」的量化，rnikhil 给出 cache-hit/cache-miss 模式。
- 但所有来源都把它当**一个 tip**——没有包格式、没有准入闸、没有质检、没有差量重铸、
  没有指纹与 fail-closed、没有双工参数随包治理。
- **本仓对照**：这四件恰是本仓的主体（compiler 预铸流水线 / docs/14 准入 / assets 四属性 /
  compiler 差量重铸 / runtime 双工参数）——**别人把缓存当技巧，我们把它做成层**。

## 二、竞品格局与差异化

| 阵营 | 代表 | 话术资产怎么做 | 与本仓的差异 |
|---|---|---|---|
| 托管平台 | Vapi / Retell | 平台内 audio caching（tip 级） | 无独立资产层概念；不可私有化审计 |
| 开源框架 | LiveKit / Pipecat | 用户自建缓存 | 管线框架不管话术治理 |
| 中国外呼厂商 | 阿里云 / Udesk / 合力亿捷 | 「500 套合规话术模板」静态配置 | 无准入判据、无质检、无实测边界、无指纹 |
| 传统 IVR | — | 预铸录音的祖宗 | 我们 = 「会按流程选 key 的 IVR 资产层 + 双工」 |
| **本仓** | vox-type | **包格式 + 准入 + 四属性 + 指纹 + 差量重铸 + 双工参数 + 实测边界** | 差异化 = 工程体系深度 × 中文合规场景 |

## 三、存在性风险：S2S 会不会吃掉级联（进而吃掉预铸）？

2026 年的行业共识（Deepgram / Modulate / Inworld / arXiv）：
- **级联在企业生产仍胜**：工具调用、transcript 可见性、调试、guardrails、按组件换供应商
  （Modulate 原话「beat the black box」）；
- **S2S 赢延迟与自然度**；趋势是 **hybrid**（原生音频理解 + 文本推理），不是赢家通吃。

对本仓的含义：
1. 级联存量市场足够大且短期不会退——钩子已在这条链路上真链路命中（第十五批）；
2. 立项方向「终局内嵌 S2S、级联是起点」与 hybrid 趋势**同向**：覆盖层的插入点
   （级联=LLM→TTS 之间；S2S=模型输出处整轮旁路）在两种架构里都成立；
3. 反而有一个**逆向机会**：模型越黑盒（S2S 化），「固定话术不经过模型」的
   **白盒确定性/合规价值**越突出——预铸层是 S2S 时代的合规锚点。

## 四、前景判断（结论）

**有前景，且切入叙事要重排**：
- **主打**：合规可审核的预铸话术资产层（中文/金融/政务/运营商场景）——痛点最硬（P3）、
  竞品最弱（模板库 vs 资产层）、我们工程形态最全；
- **附带**：高频固定话术的近零延迟（P1，2530× 实测）与确定性吞吐（P2）；
- **诚实边界**（对外表述纪律）：适用边界 = 流程决定的话轮（实测 23%）；**无槽话术已全覆盖**
  （40 单句 + 14 条多分句拆 29 句，T33；带槽 13 条按设计走原路——槽值现场合成）；
  「真链路」目前是本地 demo（kefu 供热客服），尚无生产流量；
  TTS 降价持续稀释成本主张；大平台随时可把资产层做成 feature——护城河在体系深度与
  中文合规场景，不在手法本身。

## 五、跨行业验证（2026-09-21，`labs/multi-industry-corpus/`）

> 用户指令：把适用边界从客服扩到其他行业（车机/座舱/导航等语音包密集场景），用公开语料验证。
> **全部数字以该目录落盘的 `report.json` 为准**（含 provenance：7 份语料台账 + 10 条拒收留痕）。

**拿到的三条结论（对前景论证的意义）**：

1. **「流程决定话术」占比跨行业存在，但口径依赖极强**——系统侧实测：
   **CrossWOZ（中文五域）11.86%**（n=50813，与客服 23.0% 唯一同档可比：都是标注驱动中文；
   差异来自 CrossWOZ 只有 5 类仪式 intent，而客服口径还含合规提示/转人工等专属流程轮）；
   ABCD 58.37%、MultiWOZ 2.1 64.64% 属**更宽口径**（含业务动作埋点/系统反问），不可与客服直接比；
   MultiWOZ 2.2 与 2.1 是**同一批轮次**、纯文本启发式 15.94% vs 标注驱动 64.64%——**差 48.7pp**，
   这是"任何对外数字必须带口径"的最强证据。
2. **用户侧句式复用率跨语料稳定**：MASSIVE zh-CN **1.68%**（n=16521）与客服 **1.8%**（n=25810）同档
   → 支持"**1.8% 这个量级是跨语料成立的**"（此前的 1.8% 只在催收语料上测过，属单点）。
3. **回流闭环（M3）在公开数据上可走多远有了第一组数**：CrossWOZ 上挖出 **737 条候选话术**
   （供"日志挖掘 → 话术建议"验证）。

**诚实边界（新增，必须对外守）**：**导航播报 / 机场车站广播 / 工业设备 / 政务热线 / 快递通知 =
公开数据真空**——没有任何许可干净、可验证的公开语料，**不得用近似场景冒充**；
中文车机/座舱真实语料被商业数据商垄断（唯一开放的 AISHELL-5 是 CC BY-SA、不在本仓许可白名单）。

## 五、剩余事项的优先级重排（「一个个过」的结论）

| 事项 | 原优先级 | 结合市场的重排 | 理由 |
|---|---|---|---|
| **对外叙事物**（README 对外页 / demo 视频 / 合规话术治理一页图） | 无 | **升为新候选** | 叙事重排后需要对外载体；Apache-2.0 已就位 |
| **14 条多分句「整段→plan 拼接」** | 留口子 | ~~升~~ **已落地（T33，2026-09-21）** | opening/fallback_internal 是高频句；落地形态 = 拆句铸入 + 逐字覆盖序列命中（`docs/10 §10.7`），实测 14/14、命中臂 P50 ≈ 5 ms vs 慢路 ≈ 575 ms。**下一步**：kefu 钩子接序列档（跨仓卡） |
| T19/T20 双工 | 中（立项另一半） | 维持中 | barge-in 是行业通用能力，差异化在「参数随包治理」，需落地验证 |

| T18 TTL | 低 | 维持低 | 同上 |
| golden 验收集 B（真人盲测） | 等条件 | **若对外则升** | 对外叙事需要自然度盲测背书（立项五指标之一） |
