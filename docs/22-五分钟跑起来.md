# 22 · 五分钟跑起来（给新来的人）

> **这份文档是唯一一份"教你把它跑起来"的文档**——其余 `docs/` 都是设计、口径、合规与任务卡，
> 是给**维护者**看的。你要是第一次来，从这一份开始就够了。
> **所有命令与输出都是 2026-09-23 实机跑出来的真值**（macOS / Python 3.14），不是示意。

## 0. 先说清「前置包」是什么（一句话 + 一张图）

**前置包 = 把「流程已经决定要说的那些话」提前做成音频，运行时按状态直接取——不走模型、不合成。**

```
用户说话 → [ASR] → 文本 → [谁决定这一轮说什么] → 一段音频 → 播
                              ↑
                    前置包就坐在这里
                给它「要说什么」（key + 槽位），还你一段 16kHz 音频
```

拆开是三个部件（`docs/12 §12.11`）：

| 部件 | 干什么 | 在本仓哪里 |
|---|---|---|
| ① 状态层 | 状态 → 「该说哪句话」 | `trigger/`（`state → plan` 映射） |
| ② **资产层** | 「该说哪句话」→ 声音 | `compiler/`（铸）+ `assets/`（包）+ `runtime/`（播） |
| ③ 触发与开口层 | 什么时候说、被打断怎么办 | `runtime/duplex.py` 四参数 |

**你手上会拿到的实物**，就是一个**资产包目录**（`manifest.json` + 一堆 `audio/*.wav`）——
它跟一个静态网站构建出来的 `dist/` 是同一类东西：**源码是 `packs/<业务>/`，产物是资产包**。

## 1. 一次性准备

```sh
git clone https://github.com/starmcainiao/vox-type && cd vox-type
python3 --version        # 需要 ≥ 3.12；本仓零第三方依赖，不用 pip install
sh bin/vox --help        # 先确认 CLI 在
```

真值输出：

```
usage: vox [-h] <命令> ...

vox — 预铸语音资产 CLI（薄壳：解析 → 调用各层公开 API → 打印 → 退出码）

positional arguments:
  <命令>
    pack      业务包子命令
    run       执行一条播报计划（快路；未命中默认 fail-closed）
    bench     离线对拍：快路（命中资产）vs 慢路（现场合成），出可复现报告
    verify    对任意产物跑质检（已铸包 / 包源 / eval 报告，只读）
```

> **主线：模型 TTS。** 仓内 `adapters.tts_omlx:OmlxTts` 是 OpenAI 兼容 `/v1/audio/speech`
> 客户端（`adapters/tts_omlx/adapter.py` 的 `SPEECH_ENDPOINT`），oMLX / vLLM-Omni / SGLang-Omni /
> 任意云服务说的是同一个协议；把端点用 env 指过去即可，不新增第三方依赖：
>
> ```sh
> VOX_TTS_ENDPOINT=http://<你的服务>:<端口> \
>   sh bin/vox pack build packs/heat_kefu --adapter adapters.tts_omlx:OmlxTts --out /tmp/vox-demo/heat-kefu
> ```
>
> 可选：`VOX_TTS_MODEL`（服务端模型名）、`VOX_TTS_VOICE`（服务端音色名，缺省 `default`）。
> 这条路径需要 `ffmpeg` 把常见的 24 kHz 输出归一到 16 kHz 契约（`docs/06`）；端点写错（非
> http/https）会**响亮地**抛 `ValueError`，不会悄悄换地址。`--adapter` 仍是显式参数，缺省值写在
> 冻结区 `cli/`，需开批才能改（见 `docs/13 §五`）。
>
> **macOS `say` 应急路径（脚注）**：已有 macOS 且暂不接 TTS 端点时，`pack build` 可省略
> `--adapter` 走系统自带 `say`；它只作应急，不作为跨平台主线。

## 2. 铸一个包（把源码变成资产）

主线是**模型 TTS**：`adapters.tts_omlx:OmlxTts` 说的是 OpenAI 兼容 `/v1/audio/speech`，
端点默认 `http://127.0.0.1:10099`（本机 oMLX），可用 `VOX_TTS_ENDPOINT` 指向任意兼容服务；
本命令另需 `ffmpeg` 做 16 kHz 归一。macOS 上的 `say` 仅是缺省应急路径，放在下文小节。

```sh
VOX_TTS_ENDPOINT=http://127.0.0.1:10099 \
  sh bin/vox pack build packs/heat_kefu \
      --adapter adapters.tts_omlx:OmlxTts \
      --out /tmp/vox-demo/heat-kefu
```

真值输出（两条：人读摘要走 stderr，机器读 JSON 走 stdout）：

```
pack build: 通过（total=69 synthesized=69 reused=0 clean=True out=/tmp/vox-demo/heat-kefu）
{
  "command": "pack.build",
  "source_dir": "packs/heat_kefu",
  "pack_dir": "/tmp/vox-demo/heat-kefu",
  "total": 69,
  "synthesized": 69,
  "reused": 0,
  "tts_calls": 69,
  "failed": [],
  "quality_issues": [],
  "violations": [],
  "clean": true,
  "passed": true
}
```

**看什么**：`total=69 synthesized=69` = 69 条话术全部铸成功（**预铸成功率必须 100%，带病不上线**）；
`clean=true passed=true` = 内置质检（首尾静音 / 峰值电平）全过。
**到这里你已经有了 69 段 16kHz 音频**，在 `/tmp/vox-demo/heat-kefu/audio/` 下。

### 这条命令要等多久（先有个数，别以为终端死了）

**走 oMLX 铸整包是分钟级，不是秒级。** 69 个单元要**串行**发 69 次合成请求，0.6B 模型首次冷启动
实测 68 s，后面每个单元也有自己的一两秒——整包墙钟**取决于单元数与机器**，量级在「几分钟到几十分钟」
（实测数字以 `docs/13` 的登记为准，这里不给具体值）。**这是正常的，不是卡死。**

怎么确认它还在干活（而不是终端真的挂了）：

```sh
pack build: 通过（total=69 synthesized=69 ...）   ← 人读摘要，stderr
```

适配器在**每次真正发起请求前**往 **stderr** 打一行进度（stdout 只有机器可读产物）：

```
[prebake] 12/? voice=default model=Qwen3-TTS-12Hz-0.6B-Base-bf16
```

`<n>` 是已经发出的请求数；总数适配器不知道（它只管单个合成请求），所以写 `/?`——
看到这一行数字在动就说明它在跑。**macOS 上终端缓冲是块式的，进度行可能攒几行才刷出来，
这不是停了，别去 `Ctrl+C`。**

**端点没起会立刻报错，不再静默等 67 秒。** 没起 oMLX 时 `pack build` 首抛：

```
TtsError: TTS 无法连接（urllib.error.URLError）——端点不可用；请确认服务已在跑
（或换一个在跑的端点），再以 env 指定：export VOX_TTS_ENDPOINT=http://<host>:<port>
→ http://127.0.0.1:10099/v1/audio/speech
```

连接被拒（`ECONNREFUSED`）、DNS 解析失败、TLS 证书不配对这三类都是**确定性**故障，
同一端点重试一万次也不会变，所以**发一次就抛**；服务端 5xx / 装卸窗口的 `is busy` / 超时才是
瞬时态，照旧按 `MAX_RETRIES=5` 退避重试。改端点用 `export VOX_TTS_ENDPOINT=…`，
CLI 的 `--adapter` 传不进构造参数。

## 3. 播一句（**这一步是新人最容易卡住的地方，先看这里**）

`vox run` 要一份**播报计划（plan）**——就是一个 JSON 数组，每项说"这一轮要说什么"。
**直接抄仓里的示例 plan**（T42 落成，全部用 `heat_kefu` 包里真实存在的 key；
命令照抄 [`examples/README.md`](../examples/README.md)）：

```sh
sh bin/vox run examples/plan.json --pack /tmp/vox-demo/heat-kefu --adapter adapters.tts_omlx:OmlxTts --out /tmp/vox-demo/out.wav
```

想知道 plan 长什么样、自己改一份（`examples/plan.json` 就是这种形状）：

```json
[{"key": "opening__1"}, {"key": "opening__2"}]
```

上面这份 2 单元的最小 plan 实跑真值输出：

```
run: 通过（hit=2 miss=0 fallback=0 tts_calls=0 first_audio_ms=0.5 out=/tmp/vox-demo/out.wav）
{ "command": "run", "hit_count": 2, "miss_count": 0, "fallback_count": 0,
  "tts_calls": 0, "first_audio_ms": 0.4657…, "total_duration_ms": 11021,
  "out_path": "/tmp/vox-demo/out.wav", "events": [ … ] }
```

**这就是这个项目的全部价值兑现处，看三个数**：

| 字段 | 值 | 含义 |
|---|---|---|
| `hit_count` | 2 | 两句都在包里，**没走模型** |
| `tts_calls` | **0** | **一次合成都没发生**——这是"零延迟、零成本"的字面含义 |
| `first_audio_ms` | **0.47 ms** | 第一段音频就绪耗时（对比：现场合成 500+ ms） |

**产物是真音频**（我实测校验过）：

```
$ python3 -c "import wave; w=wave.open('/tmp/vox-demo/out.wav'); print(w.getnframes(), w.getframerate(), w.getnchannels(), w.getsampwidth()*8)"
176343 16000 1 16      # 11.02 秒 / 16kHz / 单声道 / 16bit
```

**打开听一下**：`/tmp/vox-demo/out.wav`（macOS 上 `afplay /tmp/vox-demo/out.wav`）。
**你听到的两句话，就是直接从磁盘读出来的音频字节，没有任何模型参与。**

> 💡 忘了写 `--out` 也没关系——它会写到临时目录，**并在摘要行里把路径打出来**：
> `… out=<系统临时目录>/vox-run-xxxx/vox-cli.wav`。
>
> （macOS 上 `<系统临时目录>` 就是那个每用户临时目录，形态是
> `…/<单字母段>/<长随机串>/T/`（`/var` 下挂 `folders`）——
> **这里保留形态、只去掉本机那两段随机串**，那才是「问题本身的特征」；
> 被占位掉的原值见 T59 报告。）

## 一命令自证（零引擎先听见「命中即播」）

如果手头没有 TTS 端点，clone 后直接跑：

```sh
sh examples/selftest.sh
```

脚本会做环境自检、校验源包与 [`examples/prebuilt-pack/`](../examples/prebuilt-pack/)、再串一条**零引擎**
`vox run`。这里的零引擎是“不启动 TTS 服务、不发生一次合成”，不是“不给 `--adapter`”：自证包
清单登记的是 oMLX 小模型引擎身份，运行时要显式传匹配适配器，否则引擎身份闸会 fail-closed。

```sh
sh bin/vox run examples/plan.json \
    --pack examples/prebuilt-pack \
    --adapter adapters.tts_omlx:OmlxTts \
    --out /tmp/prebuilt.wav
# 期望 rc=0，hit=4 miss=0 fallback=0 tts_calls=0，产物非空
sh bin/vox verify examples/prebuilt-pack     # 期望 rc=0
```

`selftest.sh` 末行输出 `SELFTEST: PASS|PARTIAL|FAIL`；缺端点或 ffmpeg 时为 `PARTIAL`，
但零引擎自证仍应通过。完整口径见 [`examples/README.md`](../examples/README.md) 与
[`examples/prebuilt-pack/PROVENANCE.md`](../examples/prebuilt-pack/PROVENANCE.md)。

## 4. 拿数字（三个命令）

**看包里有什么、合不合规**：

```sh
sh bin/vox pack check packs/heat_kefu          # → "passed": true, "units": 69
sh bin/vox verify /tmp/vox-demo/heat-kefu      # → "kind": "asset_pack", "passed": true
```

**离线对拍（快路 vs 慢路）**——这条需要一份**语料文件**（`--corpus`，一个含 `units` 数组的 JSON 对象）。
**直接抄仓里的示例语料**（T42 落成，命令照抄 [`examples/README.md`](../examples/README.md)）：

```sh
sh bin/vox bench /tmp/vox-demo/heat-kefu --corpus examples/bench-corpus.json --out /tmp/vox-demo/bench
```

（`examples/bench-corpus.json` 的 `text` 逐字取自 `packs/heat_kefu/phrases.json`，4 个单元，
与 [`examples/plan.json`](../examples/plan.json) 同一组 key；实测 `observed_hit_rate=1.0`、门禁通过。）

想自己从包里挑别的 key 生成一份，也可以**从 manifest 里直接生成**（这样文本逐字保证一致，
也顺带学会一件事：**话术的真相源是 manifest**）：

```sh
python3 - <<'PY' > /tmp/vox-demo/corpus.json
import json, pathlib
m = json.loads(pathlib.Path("/tmp/vox-demo/heat-kefu/manifest.json").read_text(encoding="utf-8"))
want = ("opening__1", "opening__2")
units = [{"key": a["key"], "text": a["text"], "rate": a["rate_key"], "variant": a["variant"]}
         for a in m["assets"] if a["key"] in want]
print(json.dumps({"units": units}, ensure_ascii=False))
PY

sh bin/vox bench /tmp/vox-demo/heat-kefu --corpus /tmp/vox-demo/corpus.json --out /tmp/vox-demo/bench
```

真值输出（人读摘要 + 报告落盘）：

```
bench: 通过（repeats=30 seed=20260917 arms=fast,slow 报告已写入: /tmp/vox-demo/bench/report.json）（替身适配器：时序数字不得对外引用）
```

报告里最该看的是**门禁**那一段：

```json
"reference_gate": { "required_hit_rate": 0.987, "observed_hit_rate": 1.0, "passed": true }
```

即：实测命中率 1.0，过了 `docs/12` 那条 `ε ≤ 1 − p^(1/n)` 推出来的 98.7% 门槛。
产物在 `/tmp/vox-demo/bench/`（`report.json` + `raw/` + `audio/`）。

> ⚠️ **两条口径提醒**（都是它会自己打出来的）：
> ① 括号里那句「**替身适配器：时序数字不得对外引用**」——离线对拍默认用替身合成器，
> 所以**只比"命中 vs 未命中"的结构差异，不要引用它的毫秒数**；
> ② 门禁不过时 `vox bench` **退出码 4**（不是 0），跑批脚本要按这个判断。

> 💡 **语料里 `key` 和 `text` 是两个臂各自用的，别搞混**（实测确认）：
> `key` 喂**快路臂**（"查这个 key 能不能命中"），`text` 喂**慢路臂**（"现场合成这段文本"）。
> 所以**文本写错不会让命中率掉**——我实测把句号删掉，`observed_hit_rate` 仍是 1.0、门禁照过；
> 但慢路合成的字符数与时长会跟着错，**对拍就不公平了**。
> 用上面的 manifest 生成法能同时避开这个坑。

## 5. 现在**还不好用**的地方（如实列出）

跑通之后你大概会问下面几件事，我先把答案和现状写清楚——**这些是已知缺口，不是你不会用**：

| 你想做的事 | 现在怎么做 | 缺口 |

| **知道该写什么 plan** | 直接用 [`examples/plan.json`](../examples/plan.json)（4 个 `{"key": …}` 单元，全落 `packs/heat_kefu` 已铸资产）；命令照抄 [`examples/README.md`](../examples/README.md) | ✅ **已随 T42 落成真文件**：`examples/plan.json`（`run` 实测 `hit=4 miss=0 tts_calls=0` rc=0），命令照抄 `examples/README.md` |
| **跑 bench** | 直接用 [`examples/bench-corpus.json`](../examples/bench-corpus.json)；命令照抄 [`examples/README.md`](../examples/README.md) | ✅ **已随 T42 落成真文件**：`examples/bench-corpus.json`（`bench --corpus` 实测 `observed_hit_rate=1.0`、门禁通过 rc=0；语料 `text` 逐字取自 `packs/heat_kefu/phrases.json`），命令照抄 `examples/README.md` |
| **在 Linux / Windows 上跑** | **模型 TTS 主线**（`docs/22 §1` 给了可照抄的命令）：`VOX_TTS_ENDPOINT=<你的服务> sh bin/vox pack build … --adapter adapters.tts_omlx:OmlxTts` | ⚠️ **端点与音色由 env 配置**；另需 `ffmpeg`、端点在线。`--adapter` 目前要显式给，缺省值在冻结区 `cli/`，需开批 |
| **用模型引擎铸整包** | `VOX_TTS_ENDPOINT=<你的服务> sh bin/vox pack build … --adapter adapters.tts_omlx:OmlxTts`（另需 `ffmpeg`） | ✅ **可以铸整包了（T41，2026-09-23）**：T41 落地「归一失败的有界重试」后连铸三次 `packs/demo-brief` 整包 **全部 `rc=0`**（依据：连续三次实测——第 1 次重试 6 次、第 2 次 6 次、第 3 次 10 次）。**但不是"完全稳了"**：模型是**采样型**引擎，同一条文本不同次输出不同，归一自检会随机不过；靠有界重试（`MAX_RETRIES=5`、只重试随机类、每次写 stderr 留痕）吸收随机失败。前提三条都躲不掉：**`--adapter` 要显式给** + **端点在线** + **`ffmpeg`**。旧账对照（T40 实测，无重试时 3 次分别失败 1/2/3 条 = 3/96，失败 key 每次不同）见 `docs/13 §五#25` |
| **接进自己的框架** | 见 `docs/21`（Pipecat 的接缝最强）与 `docs/12 §12.15`（引用纪律） | ⚠️ 适配器还没写（kefu 钩子是第一个，见 `adapters/framework_kefu/`） |
| **读懂"为什么这么设计"** | `docs/12`（定位）/ `docs/14`（哪些话允许固定）/ `docs/21`（开源坐标） | — |

**为什么会有这些缺口（诚实说）**：这个仓的"读者"一直是 **AI 执行器**和**验收方**——
`ls docs/*.md | wc -l` = **24** 篇（2026-09-28 实测），其中**前 18 篇确实全是设计、口径、合规与逐卡验收记录**，
**那时没有任何一篇上手教程**：这是本仓实打实的债，不是笔误。
**2026-09-23 起开始补**：本文件（`docs/22`）是第一篇上手教程，配套 `examples/` 落了可跑的
`plan.json` / `bench-corpus.json` / 预铸自证包与 `selftest.sh`；`docs/23` 是第二篇 how-to。
**但补得还不够**：`docs/16`（市场验证）、`docs/17`（业界坐标）、`docs/19`（里程碑修订）仍是纯记录体，
没有对应的「怎么做」教程。所以文档密度依然很高，对第一次来的人依旧是"信息淹没有余、入口不足"。

## 6. 一页速查（贴墙用）

```sh
# 准备
git clone https://github.com/starmcainiao/vox-type && cd vox-type

# 铸包（模型 TTS 主线：OpenAI 兼容端点 + ffmpeg）
VOX_TTS_ENDPOINT=http://127.0.0.1:10099 sh bin/vox pack build packs/heat_kefu \
    --adapter adapters.tts_omlx:OmlxTts \
    --out /tmp/vox-demo/heat-kefu

# 只校验不铸
sh bin/vox pack check packs/heat_kefu

# 播一句（plan = [{"key": "..."}]；未命中默认 fail-closed 不播半句）
# 自证包/模型铸的包必须带 --adapter（引擎一致性闸在查表之前，见 §1 说明）
sh bin/vox run plan.json --pack /tmp/vox-demo/heat-kefu --adapter adapters.tts_omlx:OmlxTts --out out.wav

# 对拍出数（--corpus 必须给）
sh bin/vox bench /tmp/vox-demo/heat-kefu --corpus corpus.json --out /tmp/vox-demo/bench

# 质检任意产物
sh bin/vox verify /tmp/vox-demo/heat-kefu
```

**退出码**（冻结）：`0` 成功 / `2` 用法错 / `3` 运行期失败 / `4` 质检不通过 / `5` fail-closed 中止。

**三个你会反复用到的概念**：

| 概念 | 一句话 |
|---|---|
| **pack**（包源） | `packs/<业务>/` 下的 JSON 源码，是真相源，改话术改这里 |
| **plan** | 一串 `{key, slots, rate, variant}`——"这一轮要说什么" |
| **manifest** | 铸出来的产物清单：`key → 音频文件 + 指纹 + TTL` |
