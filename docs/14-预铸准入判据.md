# 14 · 预铸准入判据（哪些话允许"固定"）

> **本文件是 T13 的产物：把 2026-09-19 的拍板（只准流程决定话轮）成文为可判定的准入判据。**
> 判据依据 = `docs/11` 的实测数字（第八批，n=2433 真实客诉语料）+ 用户拍板（`docs/13 §八#13`）。
> 本文件管**内容准入**（这句话配不配进包）；格式校验仍归 `compiler`（一句一 variant / 三字段 / 无占位符 / 无逻辑），
> 四属性仍归 `compiler.check_properties`——本判据是它们之上的第三道闸，不替代任何一道。
> 新会话若要为任何业务包写话术，先读本文档再动笔。

---

## 一、拍板与依据（不可遗忘的数字）

**拍板（2026-09-19）**：预铸准入**只准「流程决定性话轮」**——问候/确认身份/告别/播报类 + 业务流程可枚举的 key；
**禁止从用户话术反推 key**。

实测依据（`docs/11 §11.9.4`，全部是负面数字，外推限制见该节）：

| 测量 | 数字 | 对判据的含义 |
|---|---|---|
| 逐字档命中率（输入=助手自由文本） | **0.00%**（n=2433） | 靠"用户恰好说出预铸原话"命中 = 不存在 |
| 语义档 top-1 | **11.8%**（门槛 98.7%） | 语义检索承担"让上游按 key 说话"已被否（`docs/13 §八#1`） |
| 句级可复用话轮占比 | **1.8%** | "真实语料里挑句子复用"没有量 |
| 流程决定性话轮占比 | **23.0%** | **预铸的适用边界就是这个集合** |

推论（判据的根）：**一个 key 之所以能预铸，是因为业务流程保证了"这一步必说这句话"，
不是因为"用户经常这么说"。** key 的来源只能是业务流程，永远不能是语料统计。

## 二、准入判据（准三类，禁四类）

### 准入（同时满足 A + B 才可入包）

**A. key 必须由业务流程产出**（二选一）：

| 类别 | 定义 | 可判定条款 | 例 |
|---|---|---|---|
| **A1 流程决定性话轮** | 话轮存在与否由**业务流程状态**决定，与用户说了什么无关 | 能画出「流程步骤 → key」的一一对应：流程走到第 k 步，就必说 key_k；拿掉用户，这句话依然该说 | greeting / farewell / confirm_identity / transfer_notice / please_hold |
| **A2 业务可枚举播报** | key 对应业务系统的一个**可枚举状态/结论** | 能列出该 key 家族的**完整枚举表**，且表里每一项对应业务系统的一个真实状态；枚举表由业务方确认，不是从对话里归纳 | 工单状态播报（created/assigned/done）、账单结论播报 |

**B. 话术满足全部形式条款**（已有防线的重申，违反任何一条即不准入）：

| # | 条款 | 现有防线 |
|---|---|---|
| B1 | 每个 variant 是**一句话**（无多句号拼接） | `compiler` 源校验 |
| B2 | variant 内**无占位符**（`[公司名]` 等）——槽值一律运行时现场合成 | `compiler` 源校验 + `docs/06 §6.2.5` |
| B3 | 包内**无任何逻辑**（包是数据不是代码） | `packs/AGENTS.md §⑤` |
| B4 | 全部文本**已审核**（无未审核/占位文案） | 四属性 `compiler.check_properties` |
| B5 | 语句按 `docs/14 §一` 的边界**面向流程**而非面向用户措辞——话术写"系统要说什么"，不写"猜用户想听什么" | **本判据新增，人工判定** |

### 禁止（出现任何一条即不准入）

| # | 禁入项 | 依据 |
|---|---|---|
| ⅰ | **从用户话术反推的 key**（"用户常这么说，所以铸一条"） | 逐字档 0.00%、语义档 11.8%，双实测否 |
| ⅱ | **语义模糊类 key**（"用户说啥都能往这引"的兜底话术；语义匹配兜底≠显式兜底） | 语义档已否 + T17b 裁定（兜底必须是**作者显式声明的** `when: null`） |
| ⅲ | **纯话术模板复用**（把语料里别人的话轮整句搬进包） | 句级可复用 1.8%——没有量，且有版权/语境风险 |
| ⅳ | **判据外的"高频"主张**（"这句话出现频率高所以铸一条"） | 频率不是准入依据——`docs/11` 已实测频率路线全线失败 |

## 三、验收时的操作口径（怎么用本判据）

对每个**新包/新增 key**，验收方逐条过（可打印的 checklist）：

```
□ A1/A2 之一成立，且写明该 key 的流程步骤（A1）或枚举表（A2）——写不出来的 key 不入包
□ 禁入项 ⅰ–ⅳ 全部不命中
□ B1–B4 由 vox pack check / pack build 的既有输出证明
□ B5 抽查 3 条 variant：句子的主语是"业务/系统"，不是对用户措辞的猜测
```

**A1/A2 的证明材料随包存档**（`packs/<包>/admission.md`，一页即可：每个 key 一行——类别 + 流程步骤或枚举来源）。
这是**申报制**：判据的机器化检查留口子（见 §四），现阶段验收以 `admission.md` 申报 + 验收方抽查为准。
