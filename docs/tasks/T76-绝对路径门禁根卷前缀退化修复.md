## 卡状态

## 背景（只写必需）

推送前必跑的第 ④ 条「CI 代理跑一遍」把 CI 关卡 4a/4b/5 在一个**根卷 checkout** 上试跑了一遍，
结果关卡 4a 报 `violation_count=12838`（422 个文件），把 `/` 当成 `volume-mount` 前缀，
于是每一行里的每个路径分隔符都成了一条「机器绝对路径」违规。

**这不是误报，是真缺陷，而且只在根卷上出现。** 关键事实：

1. **已公开快照的 workflow 从未跑过关卡 4a。** 已发布提交 `c3f6c1f` 的
   `.github/workflows/tests.yml` 只有 30 行、`关卡4a` 出现 **0** 次；本地 HEAD 的同名文件
   217 行、出现 **1** 次。**关卡 4a/4b/5 的第一次执行就是这次推送**，而它第一次执行就会红。
2. **GitHub runner 的 checkout 在根卷上。** `os.path.ismount("/")` 为真，
   `_mount_ancestor` 从 runner 的 checkout 目录一路向上，第一个命中的挂载点就是根 `/`。
3. **本机是绿纯属侥幸。** 本仓恰好落在**一个外接卷**上（不是根卷），
   `_mount_ancestor` 返回的是那个卷的挂载根，退化不出来。
4. **本机的系统临时目录也在根卷上**（实测其 `_mount_ancestor` 结果同样是 `/`），
   所以**在 macOS 上就能忠实复现 CI 的条件**，不必等真机。

根因在 `build_prefixes` 的三处前缀装配：`home` 有 `if ph and ph != "/"` 守卫，
`tmp` 有 `if tmp and tmp != "/"` 守卫，**唯独 `mount` 三样都没有**：

```python
mount = _mount_ancestor(root)
if mount is not None:
    machine[str(mount).rstrip("/") + "/"] = "volume-mount"
```

`str("/").rstrip("/") + "/"` 恒等于 `"/"`。**三兄弟里少一个守卫，是遗漏，不是设计。**

依赖的已交付产物：`tools/check_no_machine_paths.py`（T58 落成、T60 加固 `unscanned[]`）。

## 要改的地方（精确到函数，执行方不要自由发挥）

`build_prefixes` 里：

1. `mount` 分支补上与两个兄弟同形的守卫，**并且要挡住 `/` 本身**：
   `_mount_ancestor` 在根卷上返回的是 `Path("/")`，判 `mount is not None` 不够。
2. 装配 `machine` 之后、进 `prefixes` 循环之前，加一道**兜底**：
   任何等于 `"/"` 的键一律不得进入 `prefixes`。
   加这道兜底的 WHY 要写在注释里：三处守卫是三份可以各自漏掉的记忆，
   而漏掉的后果是十万量级的假阳性淹没真违规（静默到没人看输出）——
   兜底把"守卫被未来的改动碰掉"从一次事故降级成一个测试。

3. `home` 分支的 `os.environ.get("HOME") or ""` 只判了空，**没判 `/`**。
   同一类缺陷、同一处修复，本卡一并补上（`HOME=/` 在精简容器里是存在的）。
   这一条属于"同一个失效模式"，不是范围蔓延。
