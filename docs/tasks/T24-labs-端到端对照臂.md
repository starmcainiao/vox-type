# T24 · labs：端到端对照臂（组合版 vs S2S 端到端）——立项差异化论证的最后一格

## 卡号 / 标题
`T24 · labs[实验]：组合版（ASR→预铸/LLM→TTS）vs 端到端 S2S——延迟 + 可控性 + 可审核性对照`

## 背景

- 立项案 **§九 第 4 条「端到端对照那一臂」**——`docs/13 §六#5` 标 ❌ 未做；`docs/19 §二 M3` 把它列为待做项，
  并注明「**立项的差异化论证依赖它**」（组合版 vs 端到端版）。
- **条件探测（验收方 2026-09-22，实测）**：
  - 本机 oMLX（29 个模型）**无 S2S**——只有 ASR（`Qwen3-ASR-0.6B-8bit` / `VibeVoice-ASR-4bit`）与
    TTS（`Qwen3-TTS-12Hz-0.6B-Base-bf16` / `Voxtral-4B-TTS` / `Breeze-TTS-2`）分离件 → **本机档不可行**；
  - **云端可行**：`qwen-omni-turbo`（百炼）存在且可用——文本档 **0.39s** 返回；
    但 `modalities:["text","audio"]` 的**非流式**请求返回 `audio=False` → **音频输出需流式**
    （DashScope 口径：omni 的音频输出只走 `stream=true` 的 SSE）。
  - 凭据：`labs/cloud-bench/.env.local`（gitignored，**不得进产物**）。

## 目标（`labs/e2e-vs-cascade/`，新目录）

### 臂 A · 组合版（级联）
ASR（本机 oMLX `Qwen3-ASR-0.6B-8bit`）→ 文本 → **预铸命中**（`adapters.framework_kefu.find_hit`）→ 包内音频；
未命中 → 云端 LLM（`qwen-turbo`）+ TTS（`qwen-tts`）。
**复用既有实现**（`labs/cloud-bench/run_cloud_bench.py` 的 LLM/TTS 臂、`adapters/asr_omlx`），**不得重写一套**。

### 臂 B · 端到端 S2S
`qwen-omni-turbo` **流式**（`stream=true`）：音频输入（say 合成的用户话术）→ **音频输出**（解析 SSE 的音频块）。
测：**首字节音频延迟** 与 总时长。

### 对照维度（立项要的三条）
| 维度 | 臂 A | 臂 B |
|---|---|---|
| **延迟** | 首字节 / 总时长（预铸命中 vs 未命中两条路） | 首字节音频 / 总时长 |
| **可控性**（数字） | 同一句固定话术跑 N 次 → **逐字一致率**（预铸应 100%） | 同句跑 N 次 → 输出转写（用 `eval/cer.normalize_for_cer` 比对）的逐字一致率 |
| **可审核性** | 定性：准入判据 / 四属性 / 指纹 / 事件留痕（可审计） | 定性：黑盒，无逐字保证（写进报告，不做主观评分） |

## 验收标准（逐条可判定）

1. **两臂跑通**：各 ≥5 次采样；**臂 B 必须解析出非空音频**（若流式音频实测不可得 → **如实记"本条件下不可测"**，
   不得用文本档冒充端到端——这是本卡最重要的一条边界）。
2. **可控性有数字**：同一固定话术 N 次，臂 A 逐字一致率 = **100%**（预铸路径）；臂 B 的逐字一致率如实报
   （预期 < 100%，即"端到端不保证逐字"——这正是差异化论证的要点）。
3. **延迟对照**：首字节 + 总时长 P50（口径写清：流式/非流式、含不含网络）；与 `labs/cloud-bench` 的既有
   数字可对照（云端未命中链 ≈2.87s）。
4. **复现**：固定脚本 + 凭据从环境变量读；产物**无 key、无绝对路径、无真实会话**（扫描 0 命中）。
5. **无新增第三方依赖**（标准库 + urllib；SSE 解析手写）。
6. **十一根零回归**（报条数）。

## 反空转条款

- 臂 B 的"音频非空"必须有**字节数 + 格式校验**（不是"响应 200 就算过"）；
- 可控性的 N 次采样要**真的跑 N 次**（不是复制同一结果）；逐字比对必须走 `normalize_text`/`normalize_for_cer`（同源）；
- 若某臂因外部原因不可得，**如实写"未取到"并给出原因**，不得编数。
