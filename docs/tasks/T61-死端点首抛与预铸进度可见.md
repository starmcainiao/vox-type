# T61 · 死端点首抛不重试 + 预铸进度可见

> 状态：已执行，待验收（AC1–AC7 实测输出见 T61 报告）　｜　来源：T1 决策层「业务产品票」缺口 #3 + 本人复核
> 分区：`adapters/`（扩展区）——**不碰任何冻结区**

## 一、为什么开这张卡

外部使用者第一次装本项目时，多半没起 oMLX。此时 `vox pack build` 的表现是：

- 端点连不上 → 适配器把「无法连接」判为**可重试** → `MAX_RETRIES=5` + `RETRY_DELAYS=(2,5,10,30)` = 单条 67 秒静默等待
- 单元数 × 67 秒，全程 **stdout/stderr 零输出**，终端像死机
- 实测 `packs/demo-brief`（48 单元）≈ **54 分钟**零输出

两条都是**确定性故障被当成瞬时故障重试**。这是 D4「禁止静默降级」的同一类病：出错了但系统不告诉你。

复核证据（`adapters/tts_omlx/transport.py:62-67`）：

```python
def _retryable(self, exc: TtsError) -> bool:
    return ("HTTP 5" in text or any(m in text for m in BUSY_MARKERS)
            or any(s in text for s in ("无法连接", "超时", "TLS", "读取", "HTTPException")))
```

`"无法连接"`（ECONNREFUSED）与 `"TLS"` 是**确定性的**：同一个错端点，重试 5 次的结果与重试 1 次完全相同。`"HTTP 5"`、`BUSY_MARKERS`、`"读取"` 才可能是瞬时态。

## 二、做什么

### A. 连接类故障首抛（`adapters/tts_omlx/transport.py`）

把 `_retryable` 里的**确定性类**摘出去：

| 类别 | 现状 | 改为 |
|---|---|---|
| `无法连接`（ECONNREFUSED / DNS 失败） | 重试 | **不重试，首抛** |
| `TLS` | 重试 | **不重试，首抛** |
| `HTTP 4xx` | 不重试 | 保持 |
| `HTTP 5` | 重试 | 保持 |
| `BUSY_MARKERS` | 重试 | 保持 |
| `超时` / `读取` | 重试 | 保持 |

实现要求：
- 判定必须**基于异常类型**（`isinstance`），不是基于 `str(exc)` 里的中文子串。
  `HTTP_STAGES`（`:33`）已经把 `socket.timeout` / `ssl.SSLError` 映射成中文文案了，但 `_retryable` 拿不到原始异常——需要把原始异常带出来（见下）。
- **不得**为了让判定成立而改动 `HTTP_STAGES` 的文案（那是对外消息，测试可能断言）。
- 首抛时消息里必须带上**怎么修**（检查端点是否在跑、怎么改 `VOX_TTS_ENDPOINT`），不能让用户自己猜。

### B. 预铸进度可见（`compiler/prebake.py`）

**注意：`compiler/` 是冻结区。本卡不得改它。**

因此本卡只做适配器侧能做的事：让 `adapters/tts_omlx/adapter.py` 的 `synthesize()` 在每次真正发起请求前，往 **stderr** 打一行进度：

```
[prebake] 12/69 voice=default model=Qwen3-TTS-12Hz-0.6B-Base-bf16
```

要求：
- 走 stderr（stdout 保持只有机器可读产物）。
- 计数由适配器自己维护（`self._calls`），格式 `[prebake] <n>/? `——总数适配器不知道，**不许猜**，就打到 `<n>`。
- 必须是**请求前**打，不是完成后打——用户要看到的是「它卡在哪一条」。
- `verbosity` / 静默模式：若适配器已有开关则挂上去；没有则**不加新开关**（新增公开参数要开批），只打 stderr 不影响 stdout 契约。

### C. 文档侧把「10 分钟起步」写清楚（`docs/22-五分钟跑起来.md`）

`pack build` 走 oMLX 时，69 个单元串行合成，**墙钟是分钟级不是秒级**。`docs/22` 现在没写这件事，新人会以为是死机。补一句实测口径（数字以 T65 诊断卡的实测为准，先写「分钟级、取决于单元数与机器」）。

## 四、验收标准（每条都要能跑）

- **AC1**：`VOX_TTS_ENDPOINT` 指向死端口跑一次 `synthesize`，**只发 1 次 HTTP 请求**即抛错（不是 6 次）。
  验证：临时 opener 计数，断言请求数 `== 1`。
- **AC2**：AC1 的抛出消息里含「无法连接」且含**修复指引**（提到 `VOX_TTS_ENDPOINT`）。
- **AC3**：`HTTP 5` 仍然重试到 `MAX_RETRIES`（**别把瞬时态也砍了**）。用假 opener 连续抛 HTTP 5xx，断言请求数 `== MAX_RETRIES+1`。
