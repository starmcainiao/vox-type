# T54 · 测试分项口径随 T51/T53 刷新（`skipped=26` 已作废）

> 开批：2026-09-28 · 性质：**纯文档**（零代码、零冻结区）· 前置：T51 已交付、T53 已交付并通过注入自证

## 一、为什么有这张卡

T50（对外表述收口）把测试分项口径写进了三份对外文件，并定死一条纪律：
**「唯一出处 = 命令 `python3 tools/run_all_tests.py` 的末行，文档只放抄件，且必须标注会漂移」**。

T50 交付时 `packs` 根因仓外 yaml 路径写死而**诚实 skip 24 条**，`adapters` 2 条环境 skip，合计 `skipped=26`。
但随后两件事把这条基线作废了：

- **T51**（yaml 路径探测）把写死路径改为多候选探测，本机命中 → **`packs` 的 24 条 skip 归零**。
- **T53**（话术同源重对账）把 `packs` 从 6 红修回全绿，并新增 `admission.md`/`packs/AGENTS.md` 的记录。

**2026-09-28 主会话实跑的真实值是 `ran=1601 skipped=0 executed=1601 failed=0 failures=0 errors=0 roots=11`。**

于是三份对外文件现在同时错了**两层**：

| 层 | 现在的错法 | 正确写法 |
|---|---|---|
| 数字 | `skipped=26` / `executed=1575` | `skipped=0` / `executed=1601` |
| **解释** | 「26 条 skip 是按设计的环境相关跳过：`packs` 24 条依赖仓外 kefu 仓的 yaml（该仓不在本机即 skip，公开 CI 上恒 skip）、`adapters` 2 条需 macOS `say` 且 tmpdir 与仓库跨设备」 | **`packs` 那 24 条已不再 skip**（T51 修掉了「路径写死就 skip」这个坑）。剩下的 skip 条件是 `adapters` 里的 `@unittest.skipUnless`：需 `ffmpeg`、需 macOS `say`、需 oMLX `:10099` 在跑。**这些在本机全部满足，所以 `skipped=0`；换台机器（典型如 Linux CI）会重新出现 skip。** |

**第二层比第一层危险**：只改数字不改解释，等于留下「本机 0 条 skip，说明这 1601 条在任何环境都会跑」的错觉——
而事实是 CI（Linux）上 ffmpeg/say 都不在，`skipped` 会变。这正是 T50 立项要消灭的那类「文档说的和命令跑的不一样」。

## 三、必须写进去的四条内容

1. **真实数字**：`ran=1601 skipped=0 executed=1601 failed=0 failures=0 errors=0 roots=11`
   （口径沿用 T50 已定：`ran`=各根 `testsRun` 之和含 skip 与失败用例，`executed=ran-skipped`，`failed=failures+errors`）。
2. **`skipped=0` 是本机状态，不是契约**。必须点名剩下的 skip 条件来自 `adapters` 的
   `@unittest.skipUnless`（ffmpeg / macOS `say` / oMLX `:10099`），并说明**在无这些依赖的环境（如 Linux CI）`skipped` 会重新大于 0**。
3. **T51 的机制变化要留痕**：说明「`packs` 的同源断言此前因 yaml 路径写死而恒 skip，现改为多候选路径探测后本机不再 skip」——
   否则读者会以为这些断言一直是跑着的。
4. **保留 T50 的「不要引用本文抄件」告诫**（那是本卡的立卡前提，不是可选项），并把唯一真源指向不变。
