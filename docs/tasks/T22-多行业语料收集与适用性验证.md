### 2. 分析（跨行业适用性）

- **主指标：系统/助手侧「流程决定话轮」占比**——对 CrossWOZ / ABCD / MultiWOZ / Taskmaster 各自算一份；
  **分类口径必须复用既有脚本**（`labs/corpus-harvest/` 的 `cross_check_template_rate.py` 或同源判据），
  不得自造一套；给出**与客服 23.0% 的对照表**（含样本量、口径说明）。
- **辅指标：用户侧指令模板化率**——对 MASSIVE（zh-CN 优先）/ HWU64 算（同一套判据）；
  说明它与主指标的区别（前者测"用户怎么说话"，后者测"系统说什么"）。
- **回流闭环可行性**：用 CrossWOZ 的**系统侧对话行为标注**做一次小实验——「从会话记录里挖出
  '某个状态下系统固定说什么'的候选话术」能挖出多少条（可复现，固定种子）；这直接回答
  M3「日志挖掘 → 话术建议」在公开数据上能走多远。
- **诚实边界**：导航播报 / 机场车站广播 / 工业设备 / 政务热线 / 快递通知 = **公开数据真空**（侦察已确认）
  → 报告中**明确写出"该场景无法用公开语料验证"**，不得用近似场景冒充。

## 验收标准（逐条可判定，验收方独立复跑）

1. **收集**：每份入选语料都有台账条目（URL / 许可 / **证据位置** / sha256 / 规模），
   与平台声明**交叉核对**；语料本体落仓外，仓内 `git status` 无新增语料文件（`git status --porcelain -uall` 核对）。
2. **拒收集**：`rejected_sources` 至少含侦察清单里的 8 条（含 RiSAWOZ / SLURP / FSC / yangzailu×2 / 数据堂），
   每条有**具体理由 + 证据位置**。
3. **主指标**：CrossWOZ / ABCD / MultiWOZ / Taskmaster **各一份「流程决定话轮占比」**（含样本量 + 口径），
   并给**与客服 23.0% 的对照表**；分类判据**与既有脚本同源**（贴出处，不得自造）。
4. **可复现**：分析脚本固定种子 → 同输入两次跑结果一致（diff 核对）。
5. **回流实验**：CrossWOZ 上挖候选话术的小实验有可复现数字（挖出多少条、覆盖哪些状态）。
6. **诚实边界**：README 与 report 里明确写出"公开数据真空"的场景清单（导航播报/广播/工业/政务/快递）。
7. **零回归**：十一根全绿（报条数）；`tools` 根测试若因配置改动需更新，须说明理由。
8. 不新增第三方依赖（若某集需 pandas/pyarrow 等，**报出来停下**，由策划裁定是否用 `~/miniforge3` 跑）。
