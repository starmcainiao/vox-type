## 八项必改（逐条，附维护者复跑证据）

### A1（最高优先）· `README.md:32-33` — ASCII 图的 fail-closed 口径漏改

T72 把 SVG 副标题、`README.md:78` 英文行、`CITATION.cff:13-15` 三处都改成了
「默认中止（rc=5），显式 `--allow-fallback` 才降级」，**唯独漏了同一页的 ASCII 图**：

```
   │  四属性校验          │ +变体池+语速档         │ 显式兜底           │ 未命中 → fail-closed
   ▼                     ▼                      ▼                   ▼ 走宿主原 TTS（留痕）
```

维护者复跑证据：
```sh
sed -n '26,34p' README.md
# → 第 32-33 行正是上面那两行
```
`README.md:47` 声称 ASCII 是 SVG 的「文字等价物」，**两处现在互相矛盾**，
且这正是 T72 背景「问题 1」认定为传播风险最高的那个误读。

**改法**：把 ASCII 图那半句改成与 `README.md:78-80` 同口径
（默认中止、显式 `--allow-fallback` 才降级）。**保持 ASCII 图对齐不受破坏**——
注意第 32-33 行右侧是等宽对齐的，改文案时列宽要一起调，改完自己数一遍 `│` 的位置。

### A2 · `docs/media/architecture.svg:69` — 证据指针指错行

现在写 `证据：README.md:206-207`。但执行器自己改 README 把行号推下去了 6 行。

维护者复跑证据：
```sh
git show HEAD:README.md | grep -n "真链路命中"   # → 206
grep -n "真链路命中" README.md                   # → 212
sed -n '206,207p' README.md
# → 「**换台机器这些依赖不在，`skipped` 会上升…**」——是 skip 讨论，不是真链路证据
```

**改法**：**不要只改成 212-213**——行号指针必然被后续编辑冲掉，这次就是这么被冲掉的。
改成不依赖行号的锚点，例如 `证据：README「真链路命中」段（sha256 字节级相同）`。
验收时**不接受**任何形如 `README.md:<数字>` 的行号指针。

### A3 · `docs/media/architecture.svg:53` — 删了数字但没留出处

原「命中即拼接读出（约 0.2 ms）」已删对，现在只剩「命中即拼接读出，未命中：中止」，
**既无口径也无任何指向 README/docs 的指针**。T72 的 AC4 给了两个选项
（带口径的数字 / 删数字改为指向 README），现在是**两个都不完整**。

**改法**：补一个可点到的出处，指向 `README.md` 首屏讲首音口径的那一节
（用**小节名**不用行号，理由同 A2）。**不许补一个新的数字回来。**

### A4 · `docs/media/architecture.svg:76-77, 81-82, 86-87` — 入口带三格全指错

现在指向 `docs/08 · docs/22` / `docs/24 · runtime/` / `docs/24 · adapters/`。
T72 的 AC5 原文要求「**指向 T71 产出的三份文档**」，一格都没指：
- `docs/24 · runtime/` 指的是冻结区代码目录，不是使用文档
- `docs/24 · adapters/` 指的是目录，不是 MCP 的 README

**改法**：分别改成 T71 的三份：
- CLI → `docs/08 · docs/22`
- Python 库 → `docs/25 §3 · examples/embed_demo/`
- MCP stdio → `adapters/mcp_vox/README.md`

### A5 · `docs/media/architecture.svg:84` — 框体重叠（本卡 AC5 新引入，卡面明令禁止）

```sh
grep -n 'x="292" y="396"\|x="406" y="380"' docs/media/architecture.svg
# → 50: <rect x="406" y="380" width="240" height="98" .../>   ← runtime 框，左边缘 406
# → 84: <rect x="292" y="396" width="118" height="62" .../>   ← MCP 框，右边缘 292+118=410
```
右边缘 410 压进 runtime 框左边缘 406，**横向重叠 4px、纵向重叠 62px**，
runtime 框的左边线被 MCP 框盖住。基线（改动前）无任何内容框碰撞，**是 T72 新加入口带引入的**。

**改法**：把 MCP 框的 `x` 改 288 或 `width` 改 114，两者取一，**必须留出 ≥4px 间隙**。

### A6 · `README.md:194` — 表头仍写「环境」

现在写 `| 环境 |`。T72 的 AC6 打的靶子就是「叫环境」这个框架
（那张表的变量全是 yaml 可达性 × PyYAML，四种组合 ≠ 四种平台，文字却叫「四种环境」）。
改成 `| 配置变体 |` 之类。
**顺带**（同一处，不算新要求）：`README.md:207` 附近「下列三档」与相邻的
「四档口径表见 tools/README.md」连着读会误解——核对两处是否自洽，不自洽就统一措辞。

### A7 · `docs/25-...md:35` — 抄件数字与同文件另一处自相矛盾

```
# → run: 通过（hit=4 miss=0 fallback=0 tts_calls=0 first_audio_ms=0.8 out=/private/tmp/x.wav）
```
验收人连跑三次得 `3.6 / 0.7 / 0.8`。**同一份文档 `§3.1:208` 自己写着**

**同文件两处口径打架**。

**改法**：给 `first_audio_ms=0.8` 加与 `§3.1:208` 同款的漂移提示
（例如行尾加 `← first_audio_ms 会漂，别引用这个数`），**保留真实输出本身不改**
（那是实跑真值，删了就没证据了）。
