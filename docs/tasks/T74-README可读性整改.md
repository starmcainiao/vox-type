# T74 · 可读性整改：让新人 30 秒看懂、5 分钟跑通

> 卡状态：已派发 → 已回收 → 验收
> 依据：T1 决策层·运营票 2026-09-28 只读评审（新人视角实况 + Top 5 缺陷 + 3 条一句话文案候选）。
> **本卡只改文档可读性与两处客观缺陷，不动任何代码、不动任何冻结区。**

## 背景

用户 2026-09-28 原话：「咱们不仅给 AI 读啊，一定要给人能读明白，让别人一看，原来还是干这个事情，而并不是啊，是什么看不懂」。

运营票实测的现状（命令与输出见卡底「验收标准 1」）：

- README 首屏 25 行内出现 **14 个术语**（预铸/资产层/双工/短路/ASR/LLM/TTS/IVR/覆盖层/级联/端到端…），**没有一个在首屏被解释**；
- 「预铸」「双工」从第 6 行副标题就开始用，README 全文**从未有一句话解释「双工」是什么**（首次解释在第 43 行，术语已用 2 次之后）；
- 唯一一段完整白话解释（`English one-liner`）排在**第 75 行且是英文**；
- 第一条可执行命令在**第 59 行**，之前压着 42 行非空散文；
- `Why` 段开头是 **11 行口径免责警告**，`口径`/`P50` 各出现 6 次，新人**先建立怀疑、后建立信任**；
- `Status` 段前 22 行是「yaml 可达 × PyYAML 可导入」配置矩阵，对「要不要用我」零价值（该表 `tools/README.md:69-76` 已有完整版）。

**两处客观缺陷（非偏好，是错）**：
- **死链**：`README.md:209` 指向 `docs/09-链路级语音对拍.md`，实际文件名是 `docs/09-链路级语音对拍-本地客服智能体.md` → 新人点「出处」404；
- **同一指标两份抄件**：`README.md:120`/`:194` 写 `ran=1628`，`docs/18-开源就绪评估.md:38` 写 `ran=1602`，**两份都自称 2026-09-28 实跑**。这直接损伤「数字必须有出处」这条纪律对外的可信度。

## 目标（可验收的产物）

改 `README.md`（主战场）与 `docs/18-开源就绪评估.md`（一处数字），使首屏顺序变成：
**人话定位 → 谁该用 → 第一次来做什么 → 进阶定位 → 架构 → 30 秒跑通**。

## 逐条改法

### R1 · 首屏重排（对应缺陷 1 + 缺陷 3）

**在 `README.md:14`（现定位引文 `>` 之前）插入新人版定位块**，用运营票推荐文案 A 展开为 3–4 行，**不得含任何本项目自造词**（预铸/前置包/资产层/双工/短路/fail-closed/覆盖层/旁路/S2S/IVR 全部不许出现在这一块）：

推荐文案 A（40 字，运营票实测字数）：
> 客服电话里流程写死的那几句，提前存成音频；轮到你时直接播，不等 AI 现场生成。

要求：这个块必须回答新人三问——① 这是干什么的 ② 我什么时候该用 ③ 我什么时候不该用。

**然后把现有的 `README.md:23-24`（「**你什么时候需要它**：做客服 / 催收 / 政务 IVR……」）与 `README.md:19-21`（「第一次来？→ docs/22 · selftest.sh · examples · docs/23」）上移到定位块之后**（这两段原文一字不改，只挪位置）。

### R6 · selftest.sh 诚实化（卡点 2.4）

README 现在把 `sh examples/selftest.sh` 写成「一命令自检环境与零引擎 run」。实测：**本机 oMLX 端点在线时它会自动做一次 69 单元的全量 `pack build`**，总耗时 120–180 秒，**且中途无任何进度输出**（脚本把子命令 stdout/stderr 全吞进变量，只在最后打一行结论）。

在该命令的说明处**如实加一句**：端点在线时它会额外做一次全量铸包、可能需要几分钟、中途不出进度。**不许把它改写成「快速自检」。**

### R7 · demo 业务标注（卡点 2.3）

`examples/prebuilt-pack` 里那 4 句是供热场景（`您好，我是供热智能客服小暖` 等）。README **没有一处提示「这是示例业务，你该换成自己的」**。在「先听声音」一节**加一句**点明：演示用的是供热报修场景的示例话术，接入时把 `packs/<你的业务>/` 换成你自己的。

### R8 · 前提前置（卡点 2.5）

`pack build` 命令在 `README.md:96`，而它的前提（`VOX_TTS_ENDPOINT` + `ffmpeg`）声明在 `:129-133`，**在命令之后 33 行**。把前提**上移到该命令之前**（一句话即可，不必搬整段），并保留原处的完整说明（加一句「详见下方 ⚠️ 前提」即可，不许删原段）。

## 验收标准（逐条可判定）

1. **死链清零**：
   ```sh
   grep -o '](\([^)]*\))' README.md | sed 's/^](//; s/)$//' | sort -u | while read -r p; do
     case "$p" in http*|'#'*) continue;; esac; [ -e "$p" ] || echo "BROKEN: $p"; done
   ```
   **期望输出为空**（改动前应有 1 行 `BROKEN: docs/09-链路级语音对拍.md`）。
2. **两份抄件一致**：`grep -n 'ran=16' README.md` 与 `grep -no 'ran=16[0-9][0-9]' docs/18-开源就绪评估.md` 输出**同一个数**。
3. **新定位块零自造词**：
   ```sh
   awk 'NR>=1 && NR<=40' README.md | grep -cE '预铸|前置包|资产层|双工|短路|fail-closed|覆盖层|旁路|S2S|IVR'
   ```
   报告改动前后两个数；**改动后必须显著低于改动前**（把定位块单独圈出来时该块内应 = 0）。
4. **首屏顺序**：`grep -n '你什么时候需要它\|^## Architecture\|第一次来？' README.md` —— 「你什么时候需要它」的行号**必须小于** `## Architecture` 的行号。
5. **口径警告未删**：`grep -c '两组首音数字' README.md` **= 1**；且 `grep -n '两组首音数字' README.md` 的行号**必须大于** `grep -n '### 一眼对比' README.md` 的行号（即已移到对比表之后）。
6. **Status 压缩**：`README.md` 总行数应**明显下降**（改动前 294 行）；报告改动后行数。`T70`/`T51`/`T53`/`T59` 这些卡号不得再出现在 Status 段。
7. **诚实化两条**：`grep -c '铸包' README.md` 与 `grep -c '示例业务\|换成你自己\|你自己的业务' README.md` 均 **≥1**。
8. **前提前移**：`grep -n 'VOX_TTS_ENDPOINT' README.md | head -1` 的行号 **小于** `grep -n 'pack build' README.md | head -1` 的行号。
9. **三条论据完整**：`grep -c '^1\. \*\*流程话术在替慢链路陪跑' README.md` = 1，且第 2、3 条论据首句仍在。
10. **门禁四道全绿**（`structure_budget` **必须带 `--no-write`**）：
    ```sh
    python3 tools/check_no_machine_paths.py
    python3 tools/structure_budget/check.py --no-write
    python3 tools/check_import_direction.py
    python3 tools/run_all_tests.py
    ```
11. **白名单核查**：`git status -uall --short` 的改动**只允许**落在 `README.md` 与 `docs/18-开源就绪评估.md` 两个文件上（`docs/tasks/` 下的卡面由维护者提交，不算本卡越界）。
