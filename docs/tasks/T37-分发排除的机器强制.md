# T37 · 分发排除的机器强制（`packs/*/golden/**` 不得进公开快照）

> 层：仓库根配置 + `docs/` + `packs/AGENTS.md` 引用面
> 发现于：2026-09-23 推送前检查（用户授权「可以执行」推送时做前置核对）
> 性质：**公开仓现存违规**（不是潜在风险——公开仓 `packs/fin-cs/golden/` 已有 1.19 MB 逐字语料）

## 一、事实（实测取证）

1. 公开仓 `github.com/starmcainiao/vox-type` 的 `packs/fin-cs/golden/` 目录**存在且非空**：
   `README.md`（3110 B）+ `corpus_derived.jsonl`（**1,192,844 B / 2433 行**）——后者是第三方语料的
   **逐字原文**（`user_utterance` / `assistant_reply_free` 两字段不做改写）。
2. 仓内**三处契约**都写明它不进公开分发：
   - `packs/AGENTS.md:9`：「`golden/`：该业务的真人标注与验收用例（**不进公开分发**）」
   - `packs/fin-cs/golden/README.md`：「**发版前检查**：`git archive` / 打包脚本必须排除 `packs/*/golden/**`」
   - `docs/11 §11.7`：分发排除清单
3. `docs/20-合规自审记录.md` 的结论里写着「**分发排除已兑现**：`packs/*/golden/**` 不入公开分发」
   ——**该陈述与公开仓实际状态不符**（合规记录里的一句不实陈述，比违规本身更该记账）。
4. **根因**：仓库**没有 `.gitattributes`**，导出走 `git archive HEAD` → 它对所有跟踪文件一视同仁，
   没有任何 `export-ignore`。于是「排除 golden」**只是一句写在文档里的人工指令**，
   没有机器执行者——**已在第一次推送时就漏掉了，且没有任何东西会报错**。

## 二、目标

把「排除」从人工指令变成**机器强制**：`git archive` 产出的发布树**物理上不可能**包含 `packs/*/golden/**`。

手段：仓库根加 `.gitattributes`，用 `export-ignore` 标记（`git archive` 原生支持，零脚本、零额外步骤）。

## 五、禁止事项

1. **不删除仓内的 `packs/fin-cs/golden/`**——它是本地留用资产（真人标注与验收用例的存放处），
   本卡解决的是「它不出仓」，不是「它不存在」；
2. 不改 `packs/AGENTS.md:29` 的「真人验收用 golden」纪律；
3. 不动冻结区；不 `git add`/不提交/不推送（提交与推送由验收方执行）。

## 六、验收标准

1. **机器排除生效**：`git archive HEAD | tar -t | grep -c 'packs/.*/golden'` → **0**；
   且同一命令在**改动前**必须非 0（先跑基线，证明判据有区分度，不是空转）；
2. **不误伤**：`git archive HEAD | tar -t | grep -c 'packs/fin-cs/phrases.json'` → **1**
   （排除只作用于 golden，不是把整个 packs 排除掉）；
3. **公开仓纠正**：推送后 `gh api repos/starmcainiao/vox-type/contents/packs/fin-cs`
   返回的目录列表中**不含 `golden`**；
4. **文档陈述与实际一致**：`docs/20` 不再出现「已兑现」这类**无法当场核验**的说法，
   改为给出可执行核验命令 + 结果；
5. **本地全量测试零回归**：十一根条数与改动前逐根相同（本卡不改任何 .py）。

## 七、回滚方式

删除 `.gitattributes` 即恢复原状（`git checkout` 不了未跟踪文件用 `rm`）；
公开仓若需恢复 golden——**不恢复**，那是违规状态。

## 八、依赖

无。但**推送动作依赖本卡先验收**：在 golden 仍会被导出的情况下推送，等于把违规再钉一次。
