## 背景（只写必需）

推送前必跑的第 ④ 条「CI 代理跑一遍」在模拟 runner 条件（本机有 `say`、oMLX 离线）下试跑
CI 关卡 3，`adapters` 根报 **`errors=2`**：

```
adapters/tests/test_conformance.py:265  tts.synthesize("接口一致性测试", out)
adapters/tts_omlx/transport.py:175     raise self._classified(exc, HTTP_STAGES, "TTS 无法连接")
adapters.tts_omlx.transport.TtsError: TTS 无法连接（urllib.error.URLError）——端点不可用
Ran 361 tests … FAILED (errors=2, skipped=2)
```

**这与 T76 是同一族缺陷，且会同样把 CI 顶红**：GitHub 的 `macos-latest` **有** `say`
（所以类级 `skipUnless` 不生效），**没有** oMLX 服务（所以 `tts_omlx` 必然连不上）。
本机恰好两样都有，这一支一直是绿的。

根因在 `adapters/tests/test_conformance.py`：

- 类级门是 `@unittest.skipUnless(shutil.which("say"), …)`——**按类整体跳**；
- 但循环是 `for tts in self.adapters:`——**逐适配器跑**，`self.adapters` 来自
  `discover_adapters()`，含 `tts_macsay` **与** `tts_omlx`；
- **中间没有任何按适配器的可用性判断**。

**守卫粒度比循环粒度粗**，于是「`say` 在」被当成了「所有适配器都能合成」。
`tts_omlx` 的可用性取决于**远端服务在不在跑**，与 `say` 无关。

⚠️ 仓内文档早就把「需本机 oMLX 在跑」列成 `adapters` 根的 skip 条件
（`README.md` Status 一节、`docs/18`），**但代码从来没实现它**——
本卡是让代码追上文档，不是让文档改口。

依赖的已交付产物：`adapters/tests/test_conformance_discovery.py`（`discover_adapters()`）、
`adapters/tts_omlx/`、`adapters/tts_macsay/`。

## 设计口径（照做，不要另发明）

**「适配器自报可用性」做成一个可选类方法**，名字取 `probe_availability`：

```python
@classmethod
def probe_availability(cls) -> tuple[bool, str]:
    """返回 (能不能现在就用, 不能的原因)。子类可不实现——不实现 = 永远可用。"""
```

- **默认（父类/未实现）= 可用**。这样 `tts_macsay` 等不实现它的适配器**行为完全不变**，
  仍然被真跑一遍——**不得改成「统一都跳」**。
- `tts_omlx` 实现它：用**短超时 socket 连自己的 `base_url` 主机与端口**判活，
  连不上返回 `(False, "端点不可用：<base_url>")`。
  **仓库里已有同形先例**：`adapters/tts_omlx/tests/test_adapter.py` 里就用
  `socket.create_connection` + `skipTest` 判过本机 oMLX 在不在跑，**沿用那个写法**，
  不要另写一套探活。

**一致性套件侧**：在两个方法的循环里，逐个适配器先问一句
`getattr(type(tts), "probe_availability", None)`；
有就调，返回不可用则 `self.skipTest(...)`，**消息必须点名是哪个适配器、缺什么**；
没有该方法就照旧真跑。

## 禁止事项（这几条是本卡最容易做错的地方）

- **绝对不许把 `tts.synthesize(...)` 包进 `try/except` 里跳过。**
  那是把「真的合成失败」也变成 skip = 空套件假绿灯，与本仓「静默跳过等于零覆盖」
  的既有立场（见 `discover_adapters` 的 docstring）直接相反。
  **只允许在调用之前判定，不允许在调用之后吞异常。**
- **不许把类级 `skipUnless(shutil.which("say"))` 删掉或改宽**。
- **不许改 `discover_adapters()`**（含「空套件抛 RuntimeError」那条）。
- **不许缩小适配器发现范围**（不许把 `tts_omlx` 从发现里排掉）。
- **不许放宽断言**：格式断言（16k/单声道/16-bit/帧数>0）与速率档循环都保持原样。
- **不许新增第三方依赖**。
- 不许把 `probe_availability` 做成**必实现**的契约（那会让既有适配器全部被迫改）。

## 二、负控：真失败没有被 skip 吃掉（本卡最要紧的一条）

把 `MacSayTts.synthesize` 临时换成产出一段 **8 kHz 坏 WAV**（格式违规），

```

```

`skipped=0` / `errors=0` / `failures=2` —— 违规 WAV 被**真断言抓住**，
没有一条被降级成 skip。这正是「判定只许放在 `synthesize` 之前」的收益：
代码里 `synthesize` 周围**没有任何 try/except**。

一处必须说清的**边界**（不是缺陷，但别读成比实际更强的保证）：

omlx 那一轮根本没轮到。skip 分支在这次运行中**未被执行**；
