# T64 · 开源运营件补齐：让人找得到、提得动、引得用

> 状态：已执行（待验收）　｜　来源：T1 决策层「运营票」P1/P2/P3 + 「开发交付票」G4/G5/G7
> 分区：`README.md` / `CHANGELOG.md` / `CONTRIBUTING.md` / `.github/` / 仓根新文件
> ——**不碰任何冻结区，也不碰任何产品代码**

## 一、为什么开这张卡

决策层四票里，**运营票与开发交付票各自独立**都点了同一件事：仓里的东西大体齐了，但
**「陌生人 → star → 提 PR」这条链上有几个洞**。这些洞的修复成本极低（全是文档与配置），
但不做的话前面所有工程投入在公开面上等于不存在。

复核过的关键事实（都已实跑）：

```sh
$ git tag | wc -l            → 0          # 无 tag，外部无法锚定版本
$ grep -c -- "--root" CONTRIBUTING.md  → 0   # 只跑一根测试的用法没写进贡献指南
$ find .github -name "*.md"   → 只有 2 个 issue 模板，无 PR 模板
$ grep -n "^## " CHANGELOG.md
5:## [0.1.0] - 2026-09-19 · 首次开源
29:## [Unreleased] · 2026-09-19 之后      # 这一段 13 条全是 T43/T44/… 内部卡号
$ grep -n "yyyy" LICENSE      → LICENSE:190  # 版权行还是模板占位
$ grep -n "](#" README.md
11:[![Dependencies](...)](#quick-start)   # 徽章指向的 anchor 与实际标题不符
$ grep -rn "macOS\|Linux" CONTRIBUTING.md | wc -l → 0   # 全仓测试需 macOS say，指南零说明
```

还有一条**不是文档债、是功能债**：`vox run` 的 JSON 只给 `first_audio_ms=0.715ms`，
README 自己承认那个数**不含 Python 进程启动**。使用者自己跑一次看到的墙钟是 ~120ms，
两者差两个数量级。README 不写清楚，第一次跑的人会以为项目在吹牛。

## 二、做什么

### A. PR 模板（新建 `.github/PULL_REQUEST_TEMPLATE.md`）

三段，缺一不可：

1. **环境**：OS / Python 版本 / 有没有 `say`。
2. **自证**：`python3 tools/run_all_tests.py` 的**汇总行原文**贴上来（不是「我跑过了」）。
3. **冻结区勾选框**：本卡改到了 `core/ rules/ compiler/ assets/ runtime/ eval/ cli/` 吗？
   是 → 必须先开 issue 讨论，不许直接开 PR。
   这条是 D9 的落地。目前新人只在写完代码后才在 CONTRIBUTING 规则 6 里撞见它。

### B. issue 模板配套（新建 `.github/ISSUE_TEMPLATE/config.yml`）

- `blank_issues_enabled: true` —— 现在新人打开 New issue 只看到两个模板，
  **「我只是想问个问题」没有出口**。
- `contact_links` 至少两条：提问（指 Discussions 或 issue）、安全漏洞（指 SECURITY.md 的渠道）。
- 现有 `feature_request.md` 里有一行 `labels: design`，而 `design` 这个 label
  **在远端不存在**（`curl .../labels/design` → 404）。要么改成默认集里存在的
  `enhancement`，要么在报告里点名「需要仓库管理员建 label」——**不许假装它存在**。
- `bug_report.md` 补一栏：**你走的哪条路径**（clone 快照 / `examples/prebuilt-pack` /
  自建 pack）。本仓三条路径的环境假设完全不同，混报会浪费来回。

### C. CONTRIBUTING 补三行（都是缺了会直接撞墙的）

1. **平台前置条件**：`tools/run_all_tests.py` 的 `cli` 根需要 macOS `say`；
   无 `say` 环境下 `cli` 根会红，属**已知平台限制**（实测：模拟无 say 环境，
   `cli` 根 ran 89→26、failed 22，其余 10 根全绿）。**不要**写「全平台全绿」。
2. **只跑一根**：`python3 tools/run_all_tests.py --root cli`（全量 66s，单根 31s）。
   现在这条只记在 `tools/README.md`，两份贡献指南都没写。
3. **任务卡不是义务**：`docs/tasks/` 是维护者内部的派发机制，
   **外部贡献者不需要、也不应该开任务卡**。这一行把 60+ 张卡的噪音墙直接拆掉。

### D. README 首屏重排

现状：第一张图在第 89 行、第一条 `git clone` 在第 126 行、演示音频在第 196 行。
**3988 个字符之后才有第一张图**，而首屏第一段是口径警告。
陌生人的 10 秒在读「为什么有 0.715 和 0.232 两组数」——那是给验收方看的。

改动（**只调顺序与增补，不删任何口径警告、不改任何数字**）：

1. 一句话定位之后立刻插「**你什么时候需要它**」一行——触发条件，不是形容词。
   草稿方向：做客服 / 催收 / 政务 IVR，首响被 TTS 合成卡住，且有一部分话术是流程写死的。
2. 架构图与演示音频上提到首屏（在口径警告块之前）。
   音频保持链接形态（本仓音频是 wav，GitHub 原生 `<audio>` 不可靠），
   但要在旁边写清**复现命令**，让人知道这是能自己验的。
3. 口径警告块**下移**到「Why」之后——不删，只是别占第一屏。
4. `first_audio_ms` 旁**明确标注不含进程启动**，并给出墙钟量级对照。
   数字口径以 `labs/frontpack-value/report.json` 为准，**不许新造数字**。

### E. CHANGELOG 从内部卡号改成用户视角

`[Unreleased]` 段 13 条全是 `T43 · …` `T44 · …`。外部用户读到的应该是
「这个版本对我意味着什么」。改法：

- `[Unreleased]` 改写为 `## [0.2.0] - <今天日期>`。
- 条目用 Keep-a-Changelog 三段式（Added / Changed / Fixed）。
- **T 卡号不许删**（它们是内部索引，有价值），但要收进条目末尾的折叠块，
  或降级成「内部批次」小节。
- 每条涉及数字的，**必须标口径与样本量**（纪律 6）。数字一律从既有报告取。

### F. 三处小债

- `LICENSE:190` 版权行占位 `[yyyy] [name of copyright owner]` → 填实际权利人。
- `README.md:11` 徽章 anchor 死链 → 改成与实际标题一致。
  **做法**：把 `## Quick Start（纯标准库，Python ≥ 3.12；零第三方依赖）` 的括号去掉
  （一处解决所有 anchor 歧义），比手工转义维护 anchor 稳。
- 新建 `CITATION.cff`（GitHub 会自动渲染 "Cite this repository"）。
  `version` 字段**必须与 CHANGELOG 改完后的一致**，不许两张皮。

## 四、验收标准

- **AC1**：新建的三个文件（PR 模板 / config.yml / CITATION.cff）存在且内容符合 §二。
- **AC2**：`grep -c "macOS\|Linux" CONTRIBUTING.md` > 0，且**明确写出 `cli` 根的平台限制**，
  不许写成「全绿」。
- **AC3**：`grep -c -- "--root" CONTRIBUTING.md` > 0。
- **AC4**：CONTRIBUTING 里有一行明确说外部贡献者**不需要**开任务卡。
- **AC5**：README 第一屏内（**前 60 行**）能同时找到：定位句、「你什么时候需要它」、
  架构图、演示音频链接。给出前 60 行的实际内容自证。
- **AC6**：README 里的每一个对外数字都能在 `labs/frontpack-value/report.json` 或
  `eval/` 报告里找到出处。逐个列出「README 数字 → 出处文件:字段」。
- **AC7**：`first_audio_ms` 附近有「不含进程启动」的口径标注。
- **AC8**：CHANGELOG 有 `## [0.2.0]` 段，三段式结构，T 卡号仍可检索到
  （`grep -c "^- \*\*T4" CHANGELOG.md` 仍 > 0）。
- **AC9**：`CITATION.cff` 的 `version` 与 CHANGELOG 的 `0.2.0` **字面一致**（给 grep 输出）。
- **AC10**：`LICENSE` 不再含 `yyyy`。
- **AC11**：README 徽章 anchor 与实际标题一致——把 README 里所有 `](#...)` 抽出来，
  与所有 `^#+ ` 标题逐个核对，报告 0 处不匹配。
- **AC12**：`python3 tools/run_all_tests.py` 全绿（本卡不该动任何测试，但**要证明没动坏**）。
- **AC13**：`python3 tools/structure_budget/check.py --no-write` 全绿。
- **AC14**：`git status --porcelain` 只含 §三 白名单；冻结区零改动。

## 六、给执行者的提醒

- **不要动任何数字的取值**。AC6 是「出处可追」，不是「数字好看」。
  如果你发现某个数字**确实没有出处**，如实报告，**不要自己编一个**。
- README 重排时**不要删口径警告**——那是本项目的纪律 6。它下移，不消失。
- `docs/22` 和 `README` 都提到 `examples/prebuilt-pack`；本卡**不要**去验证它
  在公开树上是否存在（那是 T68 的事，涉及远端状态）。
- AC11 的 anchor 核对：GitHub 的 anchor 生成规则是「小写、空格转 `-`、
  去掉标点」；你无法在本地渲染，所以**改成去掉标题里的括号**是最稳的做法，
  核对的也是「去掉括号后 anchor 是否唯一无歧义」。
