## 卡号 / 标题
`T20 · eval[冻]：双工质量评测 harness——打断准确率 / 假阳性 / 轮转延迟（固定种子可复现，只测"系统主动开口"侧）`

## 背景（只写必需）

- `docs/12` 第二批第三张；`docs/13 §三` 冻结区批次最后一张。**依赖 T19**（已验收：四参数被消费 + `policy_stream` 事件流）。
- `docs/12` 的定位原话：**「只测『系统主动开口』这一侧——发起方是我们，场景可自造」**（客服场景的双工是"用户打断我"= 别人的行为，测不了；前置包场景是"我什么时候该开口"= 我们自己的行为，可自造可测）。
- 本仓 runtime 是**离线产物生成器**（plan → WAV + 事件流，`policy_stream=True` 时带双工策略字段）——
  所以双工质量指标**全部从事件流算**，不需要真实音频/实时播放。
- 立项案 §五：「先有数据，再有开源。每条指标都必须可复现（脚本入库 + 固定语料 + 固定话术集）」。

## 目标

在 `eval/` 下新增**双工质量评测 harness**（`eval/duplex_quality.py` 或等价命名）：

```
输入：① duplex 参数集（patience_ms / backchannel / barge_in / rate_band 的若干组合）
     ② 用户行为脚本（自造，固定种子生成；形如 [{at_ms, action}]，action ∈ {barge_in, speak, silence}）
     ③ 已构建的资产包
过程：按 T19 的 policy_stream 事件流（每单元带 barge_in / requires_confirm / spoken_ms 等）
     判定每个用户行为落在哪个单元、该单元的打断策略是什么
输出：报告（三指标 + 中间量），落盘 JSON
```

**三指标口径（本卡裁定，写进 README 与 eval/AGENTS.md）**：

| 指标 | 定义（可判定） |
|---|---|
| **打断准确率** | 对脚本里每个 `barge_in` 动作：它落在某单元上，该单元若 `barge_in=allow`（或 `confirm` 但非 `requires_confirm`）→ 判"应允许"；若 `requires_confirm=true` → 判"应拦下等确认"。准确率 = 判定与脚本期望一致的动作数 / 总动作数（脚本期望由**生成规则**定义：生成时记录"该动作是否应被拦"，与事件流判定独立比对） |
| **假阳性** | 脚本里 `speak`/`silence` 动作（**非打断**）被系统判为"打断需拦"的比例——越低越好（0 为理想） |
| **轮转延迟** | 从"最后一个单元播完"到"等待窗口结束"的时长（= `listen_ms`，来自 T19 的等待窗口事件）+ 单元间切换耗时（`silence_pad_ms` 累计）；单位 ms，报 P50/P99 |

- **可复现**：固定种子 → 同一 (参数集, 种子, 包) 跑两次报告**逐字节一致**（除时间戳字段）；
- **场景自造**：脚本生成器不得读任何真实用户数据（本仓公开纪律）；
- **负例**：空脚本 / 非法参数 / 未构建的包 → 明确报错（不产出半份报告）。

## 验收标准（逐条可判定，验收方独立复跑）

1. **三指标可算**：对同一包 + 固定种子 + 一组参数，报告含三指标（含中间量：动作数、判定明细、
   `listen_ms` 取值）——**验收方用自写脚本从事件流独立复算其中至少两个指标**，与报告逐位一致。
2. **可复现**：同一输入连跑两次，报告除时间戳外**逐字节一致**（`diff` 核对）；换种子 → 报告变（证明种子真起作用）。
3. **口径与边界**：`eval/AGENTS.md` 含三指标的定义 + 「只测系统主动开口侧」的边界声明 + 复现命令；
   报告里带 `provenance`（包 manifest sha256 + 参数集 + 种子 + 本仓 commit）。
4. **负例**：空脚本 → 报错（消息含"空"与实际值）；非法 duplex 参数 → 报错（引 `DuplexError` 语义）；
   包不存在 → 报错；**任何一条都不得产出半份报告**（退出码非 0 且无 report.json）。
5. **无真实数据**：全仓 grep 确认生成器不读任何外部语料/录音（只吃种子与参数）。
6. **既有断言零改动**：`eval/tests` 既有断言行逐字节不变（`diff` 核对）。
7. **十一根全绿**：报每根 `Ran N` + `OK/FAILED` + 退出码（**以行为准**）；packs 需先 build + 设 `KEFU_HEAT_YAML`。

## 反空转条款

- 指标断言必须能判红：把某指标算成常数 → 对应用例必须失败（注入验证写进报告）；
- 「可复现」断言必须能判红：把种子改成固定常数（忽略入参）→ 换种子用例必须失败；
- 测试必须调用产品 API（harness 入口 + 真包），不得在测试内自造事件流。
