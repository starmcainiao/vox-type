# T67 · 把适配器契约从 hasattr 提成可 import 的声明（冻结区·待开批）

> 状态：**待开批**（`core/` + `runtime/` 是冻结区）
> 来源：T1 决策层「架构票」缺口 ① ④⑤
> **本卡只起草，执行与否由维护者拍板。**

## 一、问题（已复核）

本项目的**头号架构承诺**是 D8 宿主无关 + D3 适配器不改内核。复核结论：

**承诺是真的**（我在仓外写了 20 行假适配器，直接喂给冻结的 `runtime.Executor`，
产出合法 WAV + 事件流，内核一行没改，零反向依赖）。

**但没有任何一行代码在守它。** 全仓 0 个 ABC / 0 个 `Protocol` / 0 个 `@abstractmethod`：

```python
# runtime/executor.py:185-193 —— 契约的全部内容
@staticmethod
def _check_adapter(adapter) -> None:
    missing = [name for name in ("synthesize", "voice", "model_version")
               if not hasattr(adapter, name)]
```

三个后果：

1. **接入方唯一的「接口文档」是冻结文件里的三个词。** 改内核的人随时能改这三个词，
   而**没有任何一处会失败**——没有测试引用它，没有类型检查它。
2. **失败点被推迟到执行中途。** `__init__` 只查属性**存在**，不查**签名**。
   一个 `synthesize(text, path)` 少写 `rate_key` 的适配器能顺利通过构造，
   直到 `execute()` 跑到 `:254` 才炸——那时判定已经写了、可能已经读了包。
3. **`requires_core` 是装饰品。** 全仓零 semver 解析：适配器写 `"^0.1"`，
   内核**从不检查**。为 v0.2 内核写的适配器会静默加载。

## 二、为什么必须开冻结区

要新建 `core/adapter_api.py`（冻结区），并让 `runtime/executor.py`（冻结区）调它。
**T63 已经把「冻结区不许 import 扩展区」做成了机器门禁**——这张卡做完，
新门禁会**第一次**扫到 `core/` 里的新文件，是一次真实的自证。

## 三、做什么

1. 新建 `core/adapter_api.py`：用 `typing.Protocol`（**不用 ABC**——`isinstance` 对
   Protocol 需要 `@runtime_checkable`，而**结构化子类型**正是这个项目要的：
   外部适配器**不该**继承任何东西）声明 `TtsAdapter`，含 `synthesize` / `voice` / `model_version`。
2. `runtime/executor.py:185-193` 改成 `isinstance(adapter, TtsAdapter)`。
3. `requires_core` 真的校验：至少认 `^0.1` 一个区间，不匹配时**明确报错**而不是静默加载。
4. **先解决契约分叉再固化。** 现在三处说法不一致：
   - 内核认 3 个成员（`synthesize` / `voice` / `model_version`）
   - conformance 文档说有 6 个（多 `name` / `rate_map` / `requires_core`）
   - `rate_value` / `rate_map` **内核一次都没调用过**（`grep "adapter\.rate_value" runtime/` 空）

   `Protocol` 里**只放内核真正消费的**，其余的要么删、要么补上真实调用点。
   **不许**把 6 个都塞进去——那会让接入方为一个内核不读的成员白写实现。

## 四、验收（开批后执行）

- AC1：`core/adapter_api.py` 存在，`TtsAdapter` 可 import，成员集 == 内核实际消费集
  （用 grep 自证：Protocol 里每个名字都能在 `runtime/` 找到 `adapter.<name>` 的调用点）。
- AC2：**反向自证**——一个少写 `rate_key` 参数的适配器，**在构造时**就失败，
  不是在 `execute()` 中途失败。给出两种实现的实际输出。
- AC3：仓外写一个全新适配器（不继承任何东西）→ 通过 `isinstance` 检查 → 跑通。
- AC4：声明了不兼容 `requires_core` 的适配器被**明确拒绝**，且错误消息指出实际版本与要求区间。
- AC5：`tools/check_import_direction.py` 仍 exit 0（`core/` 新文件不得 import 扩展区）。
- AC6：`tools/run_all_tests.py` 全绿。
- AC7：T62 落地的 conformance 套件改为**从 Protocol 反射生成**断言，而不是各写一套。

## 五、待维护者决定

1. **`requires_core` 校验失败时是拒绝加载还是只警告**？D4 倾向拒绝，
   但那会让旧适配器一夜全挂。**迁移期怎么走**（先警告一个版本、再拒绝）需要拍板。
2. **契约分叉怎么裁**——删掉内核不消费的成员（会破坏外部已有适配器），
   还是给它们补真实调用点（会让内核长出新职责）？建议先只固化内核消费的那 3 个，
   其余留在 conformance 文档里，**下批再议**。
