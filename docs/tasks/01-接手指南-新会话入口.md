## 一、项目是什么

**vox-type**：语音链路的**预铸资产层 + 双工行为控制器**。
一句话：**让语音链路里固定的话术零延迟、零成本、可审核；只有不确定的部分才动用模型。**
定位：**可短路语音栈的覆盖层**——级联链路（ASR→LLM→TTS）里坐在 LLM 与 TTS 之间；端到端语音模型里做整轮旁路。
终局（用户定的方向）：把机制内嵌进**开源的端到端 S2S 小模型**；级联验证是起点。

## 五、纪律（踩过坑的，逐条都是真教训）

1. **模型自评不可信**：T01 时执行模型自述"验收 1–8 全 ✅"，实际两条未实现；T01b 自述"新增 6 条测试"实际 +4 条。**只认仓库事实与实测输出。**
2. **反空转**：测试必须调用产品 API；T01 出现过"测试文件内自带校验函数，测的是自己"——绿但等于没测。验卡时 grep 核对。
3. **fail-closed**：未命中/未知输入必须抛错或留痕，**禁止静默降级**（语音链路的静默降级=突然换声音，事后无法定位）。
4. **内核冻结 / 插件扩展**：业务侧只碰 `packs/`；改内核契约要升大版本 + 迁移说明。
5. **敏感数据红线**：本仓是**公开预备仓**——用户录音、真实会话、内网地址/token **一律不得进仓、不得派发**（免费档有数据留存风险；付费档同样是外发，条件相同）。
6. **每批一提交**：验收通过的产物立刻 `git add -A && git commit`，形成可回滚基线。
7. **回滚注意**：新产物若未跟踪，`git checkout` 无效；用 `git clean -fd <路径>`（`__pycache__` 需 `-x`）。**修订卡（`XXb` 等）在派发前要先把原卡产物提交入库**，否则 `git checkout --` 回滚对修订目标无效（T03→T03b、T04→T04b 都是这么做的）。
8. **派发指令必须写明「非交互环境」**：免费模型可能先写一份计划文件、再反问"准备好执行了吗"就结束（T02 第一轮 129s 全废）。指令里要写"直接落地，不要先出计划再等确认"。
9. **越界产物两类**（本批都踩过）：① 免费模型会在仓内写自己的计划文件（实测 `.hermes/plans/*.md`）；② `git add -A` 会把 ZCode 会话计划（`.zcode/plans/plan-sess_*.md`）一并扫进提交。两者现已进 `.gitignore`；验收时用 `git status --porcelain -uall` 核对，别只看 `git status`。
10. **源码级审计是固定动作**：本批在 T03/T04 验收通过后按红线调 `blackiron-silent-failure-hunter` 扫了一遍，查出 **1 条阻塞**（重复身份条目 → `validate_pack` 判"健康"而新条目永远查不到）+ 9 条建议，直接产出 T03c/T04c/T03d 三张卡。**卡的六条标准全过 ≠ 可以收工**——审计发现的是"标准没覆盖但会咬人"的那一类。
11. **改外部工具配置前先确认「哪一份是生效的」**（2026-09-17 真教训）：ZCode 的配置写在 **`dataBaseDir`** 下（`~/.zcode/v2/setting.json` 里的 `dataBaseDir`），另有一份同名的 `~/.zcode/v2/config.json` 是**不生效**的旧份。上个会话只改了后者，导致"商汤 provider 的 `kind`/`baseURL` 修复"整整一天都没生效，而所有人都以为改好了。**判据**：看 `setting.json` 的 `dataBaseDir`、看当天日志落在哪个 `logs/`、`ls -lat` 比两份的 mtime；**改配置就两份对齐 + 备份**。
12. **卡里的数字也要被验**（两次同类事故）：T05 卡写 `synthesized == 1`（应为该 variant 的档数）、T08 卡写 `precast_ratio == 1.0`（分母含静音垫，数学上不可能），**两次都是卡数错、实现对**。验收时凡"精确等于某值"的判据，先自己独立复算一遍再落判定；发现卡错就**在卡内更正并注明**（不要悄悄放过，也不要改实现去迁就卡）。
13. **`cmd | tail` 之后的 `$?` 是 `tail` 的退出码，不是 `cmd` 的**（2026-09-19 实测踩到）：
    我用 `python3 run_e2e.py 2>&1 | tail -6; echo rc=$?` 验一个被中断的脚本，得到 **rc=0** 并据此判定「脚本能跑」——
    而脚本实际以 `NameError` 崩了（退出码 3）。**管道会把退出码换成最后一个命令的**，这类测量错误**能把失败藏起来**，
    比失败本身更危险。判退出码一律：`cmd >out 2>&1; echo $?`（不接管道），或显式用 `set -o pipefail` / `${pipestatus[1]}`。
    **凡「跑过了/通过了」这类结论，先确认自己量的是谁的退出码。**
14. **执行方也可能反过来指出口径冲突**：T08 执行方主动提了两处争议（`precast_ratio` 分母、`percentile` 索引基准），裁定方式 = **独立复算**（我用 numpy 2.4.4 对照 R-7 线性插值；用 `wave` 自己数帧算比值）。**不采信任何一方的自述，只认复算结果。**
