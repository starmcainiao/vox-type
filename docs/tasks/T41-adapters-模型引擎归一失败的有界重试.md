# T41 · 模型引擎的「归一失败」有界重试（让模型路径能铸整包）

> 层：`adapters/`（扩展区）
> 起因：T40 验收实测（2026-09-23）——**模型引擎铸整包会随机失败**
> 性质：**阻塞「Linux 上用模型 TTS」这条方向的最后一关**（T40 只把管道接通了）

## 一、问题（实测，非推测）

模型引擎是**采样型**，同一条文本不同次输出不同。T40 验收的三组证据：

| 证据 | 结果 |
|---|---|
| `pack build packs/demo-brief`（48 条）走 oMLX | 第一次 **1 条失败**、第二次 **2 条失败**、更早一次 **3 条失败**——**失败 key 每次不同**（合计 3/96） |
| 对同一条文本连续调 8 次（复核员实测） | **8 次输出 sha256 全部不同**；时长 2480–4000 ms 浮动；24k 原始首静音 **4.0–666.2 ms** 浮动 |
| 同一个包走 macOS `say` | **48/48 通过**（`rc=0`）——确定性引擎 |

失败信息形态：`TtsError: 产物归一失败: 归一后头静音仍超限: 310.3 ms > 100 ms`（或尾静音 > 150 ms）。

**为什么这是阻塞**：本仓纪律是「**预铸成功率必须 100%，带病不上线**」（`packs/AGENTS.md §③`）。
采样引擎的随机失败让一个 48 条的包几乎必然跌破 100%——于是「Linux 上用模型 TTS」在**整包场景**
下不成立。单句合成是好的（实测同一条文本 10/10 过闸）。

## 二、目标

让**随机型**的归一失败被有界重试吸收，使模型引擎能稳定铸整包：

- **重试范围**：只在「产物归一自检不过」这一类**随机失败**上重试；
  **不重试**确定性失败（空文本 / 未知语速档 / 非 2xx 业务错误 / 缺 ffmpeg——那些重试一万次也不会变）；
- **有界**：沿用既有 `MAX_RETRIES` / `RETRY_DELAYS`（不得新引入无界循环）；
- **留痕**：每次重试必须计数并写进失败报告（**静默重试 = 把引擎的不稳定藏起来**，撞红线）；
- **最终失败仍响亮**：重试耗尽后抛的错与今天一致（`TtsError` + 具体超限值与 key）。

## 五、禁止事项

1. **不动冻结区**（`compiler/quality.py` 的 `MAX_HEAD_SILENCE_MS=100` / `MAX_TAIL_SILENCE_MS=150` 是冻结阈值——

## 六、验收标准

1. **能铸整包**：用 oMLX 端点铸 `packs/demo-brief`（48 条）**连续三次都 `rc=0`**（这是本卡存在的理由）；
   并如实报告三次各自的「重试次数总和」——**如果重试次数很高（例如 > 10%），说明引擎不稳，
   要在报告里明说，不许当成正常**；
2. **不重试确定性失败**：构造一个确定性错误（缺 ffmpeg / 空文本）→ 重试次数必须为 **0**，且消息与今天一致；
3. **重试被计数且可见**：构建报告的 `failed` / 新增字段里能看到重试次数；重试成功的那条不得静默通过；
4. **有界**：把替身 runner 设成恒失败 → 必须在 `MAX_RETRIES` 次内停下（不得超时挂死）；
5. **反空转注入**：把重试逻辑去掉 → 第 1 条（三次 rc=0）必须失败（证明重试真的在起作用）；
6. **结构预算合规**：`python3 tools/structure_budget/check.py` 退出 0（选 B 则豁免数不得超过 1 条新增）；
7. **零回归 + 双档**：`adapters` 根在 3.14 与 3.12 下均全绿。
