# 12 · 前置包：定位、形态与剩余任务

> 本文件回答三个问题：**前置包到底是什么（一句话讲明白）**、**它坐在哪**、**还剩哪些活**。
> 上游：`docs/10 §10.1`（接缝在哪）、`docs/11`（语料自给与语义检索口径）、`labs/corpus-harvest-2026-09-18/`（全部实测数字）。
> 本文件是**机制侧规格**（放公开仓）；具体某个前置包的数据源（个人记忆层/日程）属私域，另开卡。

---

## 12.1 一句话

> **前置包：把「流程已经决定要说的那些话」提前录成声音，按状态直接取。**
> **流程能定的，不经过模型；流程定不了的，才交给模型。**

## 12.2 它像什么、不是什么（**这一节是全部**）

| 像什么 | 相同点 | **关键差别（别混）** |
|---|---|---|
| **IVR 预录音** | 都是提前录好、直接播 | 前置包按**流程状态**寻址（不是按键菜单），能插槽位、能走多轮、有未命中兜底与质检 |
| **音频缓存** | 命中就省掉合成 | 缓存按**内容**寻址：必须先算出来才知道能不能命中。**实测这条路命中率 0.00%**（LLM 措辞次次不同，99.4% 的句子全库唯一）。前置包按**状态**寻址，**命中是设计出来的，不是碰运气** |
| **微调 / 端到端模型** | 都能让固定的话不用现算 | 前置包是**数据不是权重**：改一句 = 改一行 JSON 重铸，可审核、可版本化、可回滚；命中是**磁盘读**（实测 0.14 ms），不是一次前向推理（实测实时合成 515–587 ms） |

**所以它不是"缓存语音"，是「按状态寻址的声音资产」。**
"缓存"这个词会把人带向"按内容寻址"，而那正是被实测否掉的那条路（`docs/11 §11.9.4`）。

## 12.3 它坐在哪

```
用户音频 → [ASR] → 文本 → [编排/状态机] → 「这一轮要说什么」 → [TTS] → 音频
                                              ↑
                                    前置包坐在这里（一个接缝）
```

**输入**：一个「要说什么」的表示（key + 槽位 + 语速档）。
**输出**：一段音频，以及它怎么播（语速/留白/开口策略）。
**不碰**：ASR、不猜"该说什么"、不做语义判定。

同一条接缝上，**慢路**（现场合成）永远保留作兜底；前置包只是让它**大多数时候不被用到**。

## 12.4 边界（用实测数字钉住，不含糊）

实测样本：1855 通真实客服电话 / 25810 个客服话轮（`labs/corpus-harvest-2026-09-18/`）。

| 话轮类型 | 由谁决定说什么 | 占比 | 前置包 |
|---|---|---|---|
| **流程性**：问候、确认身份、告别、合规提示、请稍等、未听清重试、转人工 | **流程** | **23.0%** | ✅ 命中率 100%（key 由流程给，实测 bench hit_rate = 1.0） |
| **内容性**：信息传达、提供建议、解决实施、共情 | **现场内容** | 77.0% | ❌ 每轮内容不同，句式 98%+ 不重复 |

**对外必须这么讲**：前置包让**流程决定的那部分**话术零延迟——**不是"全部固定部分"**。
"从用户话术反推该说什么"这条路已实测不可行（top-1 11.8%，与门槛 98.7% 差 8 倍）。

## 12.5 形态：三个部件

| 部件 | 干什么 | 现状 |
|---|---|---|
| **① 状态层**（状态 → 结论项） | 从记忆/待办/日程算出「现在该说什么」：`{key, slots}` | ⚠️ 内容生成有参考实现（黑铁 `brief.py`）；**无"结论层"落库**；**无待办/跟进数据模型** |
| **② 资产层**（结论项 → 声音） | 预铸、质检、按 key 取、槽值现场合成 | ✅ **已有**：`compiler/` 预铸流水线、`assets/` 包格式、`runtime/` 执行器（八层 760 条测试） |
| **③ 触发与开口层** | 什么时候说、说完怎么办、被打断怎么办 | ❌ **缺失**：无 `state → plan` 触发器；`patience_ms`/`backchannel`/`barge_in`/`rate_band` 四个参数**全仓零消费方** |

**已有可复用**（黑铁侧）：`brief.py`（播报内容生成，13 KB）、`wechat-send.py`（投递）、launchd 定时惯例、`organs/voice/`（语音出入口）、记忆层 7094 行（L1 事实 338 条）。

## 12.6 剩余任务清单

> 编号接 T15（方言链路，仍被音频源阻塞）。**每张卡都要有自己的验收与负例**；口径照根 `AGENTS.md`。
> **归属**：`[公开]` = vox-type（机制，可开源）；`[私域]` = 黑铁仓（数据源，不进公开仓）。

### 第一批 · 让"前置包"变成可验收的机制

| 卡 | 层 | 目标 | 验收要点 |
|---|---|---|---|
| **T16** `[公开]` | core+compiler | **前置包的包形态定稿**：定义"状态键"写法（key 来自状态项而非流程步骤）与 `state → plan` 映射文件格式 | `vox pack check\|build\|bench` 三关过；负例：状态缺项 → fail-closed 不播；同一状态快照 → 同一 plan（确定性） |
| **T17** `[公开]` | runtime | **触发器**：给定状态快照 JSON → 产出 plan（新增，不动既有执行器契约） | 负例：缺 key / 未知状态项 → 抛错不静默；事件流含触发来源留痕 |
| **T18** `[公开]` | runtime | **TTL / 失效**（立项案 §4.2 的 `ttl`/`invalid_at`，**在前置包场景是刚需**） | 过期资产被引用 → fail-closed；负例：`invalid_at` 早于当前时间必须拒播（**播报过期事实比不播更糟**） |

> **为什么 TTL 提到第一批**：在企业包里过期是"话不对"；在个人前置包里过期是**"你可能照着错的信息行动"**——
> 同一个机制，个人场景下风险更高。立项案 §4.2 点名它是"防致命 bug"。

### 第二批 · 项目名字的另一半（双工），在这里才可测

| 卡 | 层 | 目标 | 验收要点 |
|---|---|---|---|
| **T19** `[公开]` | runtime | **开口策略**：把 `patience_ms`/`backchannel`/`barge_in`/`rate_band` 从"只校验"变成"被消费" | 四参数各有至少一个**可观测行为** + 事件留痕；负例：非法值仍抛 `DuplexError`（校验强度只增不减） |
| **T20** `[公开]` | eval | **双工质量指标**：打断准确率 / 假阳性 / 轮转延迟（立项案 §五 第 5 项） | 可复现（固定种子）；**只测"系统主动开口"这一侧**——发起方是我们，场景可自造 |

> **为什么双工在这里立得住**：客服场景里双工是"用户打断我怎么办"= 别人的行为，我们没有真实双工音频，测不了。
> 前置包里双工是"**我什么时候该开口**"= 我们自己的行为，可自造场景、可测。
> 这是双工控制器第一个能真验收的场景（`patience_ms`=我现在忙不忙 / `backchannel`=我在做别的事时的短确认 /
> `barge_in`=我开口时你正在说话要不要等 / `rate_band`=播报语速随场景收敛）。

## 12.7 一句话对外话术（可直接抄进 README 首屏）

> **前置包让语音 Agent 里"已经被决定要说的那些话"变成磁盘读，而不是一次前向推理。**
>
> 它像预录音，但按**状态**寻址而不是按菜单；它像缓存，但命中是**设计出来的**而不是碰运气
> （按内容的缓存实测命中 0.00%）；它像微调，但它是**数据不是权重**——改一句话就是改一行 JSON。
>
> 实测：命中路径首帧 **0.14 ms**、TTS 调用 **0 次**；同引擎实时合成 **515–587 ms**。
> 边界同样实测：在真实客诉语料里，**流程决定性话轮占 23.0%**，其余 77% 每轮内容不同、不适合预铸。

## 12.8 两个待拍板（不阻塞上面任何一张卡）

1. **人格/日记能否进前置包**——它们是既有红线（`PROTECTED_DIRS`，人格数据 Fernet 加密、原文不出本机），
   而"懂自己"最核心的数据恰在那里。T21 需要这个答案才能定数据源边界。
2. **日频播报当初为什么砍掉**（2026-08-04 把 `morning-brief` 8:00 并进了周频）——
   若是"太吵/没用"，T25 的噪音预算是第一优先；若是"维护麻烦"，T23 直接复活即可。仓库里没有记录。
