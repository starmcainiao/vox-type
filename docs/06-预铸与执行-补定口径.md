# 06 · 预铸与执行：策划补定口径（T05 / T07 前置）

> 背景：设计基础文档（内部设计仓（未公开）：`docs/语音/讨论-预铸语音资产层-设计基础-2026-09-16.md`、`立项案-…`）
> 对**预铸流水线**与**执行器**给了方向与部分数值，但对"质检门判据""未命中默认行为""槽位拼接参数"等
> 存在**未给**或**多处不一致**的地方。本文件把 T05/T07 必须钉死的口径一次性定下来，
> 遵守仓库纪律「设计变更先改文档 → 再改卡」，并区分三类来源：
>
> - **【设计原样】**：设计文档/层 AGENTS.md 已明确规定，直接沿用；
> - **【策划补定】**：设计文档未给，由本文件钉死；标注依据（实测 / 推导 / 待回填）；
> - **【明确推迟】**：本轮不做，写明推迟理由与落点（避免"静默替换"）。

## 6.1 预铸流水线（compiler / T05）

### 6.1.1 流水线步骤【设计原样】

`立项案 §二.6`：**话术枚举 → 批量合成（多语速档/多变体）→ 自动质检（头尾静音/削波/响度归一）→ 入库**。
`compiler/AGENTS.md §①`：产物 = 资产包 + 校验报告（JSON）+ 预铸账。

### 6.1.2 源格式【策划补定】

`packs/<业务>/` 下两个文件（本文件定义，T05 实现装载器）：

- `pack.json`：包元数据与默认参数——`pack_id` / `pack_version` / `protocol_version` / `ruleset_version` /
  `voice` / `model_version` / `rates`（要预铸的语速档，默认 `["normal"]`）。
- `phrases.json`：话术表——`{"phrases": [{"key", "variants": ["整句话术", …], "rates": ["slow", …]}, …]}`。
  - `variants`：同一 key 的多个说法（防复读机）；**每个元素必须是一句完整话术**。
    这落实设计红线「字模最小粒度 = 一句（含完整语调轮廓）」（`docs/03-design-nodes §3.1`）——
    **不得把多句塞进一个 variant**；长流程应拆成多个 key。
  - `rates`：该 key 要预铸的语速档（缺省用 `pack.json` 的 `rates`）。
- 剧本（`script.json`）**不属于 T05 的输入**——剧本的四属性校验是 T06 的职责，T05 只编译话术。

### 6.1.3 质检门判据【策划补定，含实测依据】

先给实测：本机 `say -v Tingting --data-format=LEI16@16000` 直出的 4 条样音：

| 文本 | 时长 ms | 头静音 ms | 尾静音 ms | 峰值 dBFS | 满幅样本 |
|---|---|---|---|---|---|
| 您好，请问需要什么帮助 | 2237 | 6.4 | 25.2 | −3.47 | 0 |
| 请提供您的手机号码 | 1830 | 16.2 | 31.2 | −4.60 | 0 |
| 我们已收到您的报修申请，稍后会有师傅与您联系 | 4453 | 4.3 | 22.7 | −3.84 | 0 |
| 是的 | 352 | 9.4 | 28.2 | −6.53 | 0 |

据此钉（阈值取实测值留足余量，既能过正常样音、又能拦住明显坏件）：

| 检查项 | 判据 | 依据 |
|---|---|---|
| 采样率 / 声道 / 位深 | 必须 16000 Hz / 1 声道 / 16-bit | 【设计原样】`docs/02-protocols-draft` 与 T03 已冻结 |
| 帧数 | > 0 且 **时长 ≤ 30000 ms** | 【策划补定】超 30s 说明没按"一句"拆 |
| 头静音 | **≤ 100 ms**；超阈 → 拒 | 【策划补定】实测最大 16.2ms，留 6 倍余量 |
| 尾静音 | **≤ 150 ms**；超阈 → 拒 | 【策划补定】实测最大 31.2ms，留约 5 倍余量 |
| 削波 | **满幅样本数（\|s\| ≥ 32767）必须 = 0**；否则拒 | 【设计原样】"削波"检查 |
| 峰值电平带 | **−20 dBFS ≤ 峰值 ≤ −1 dBFS** | 【策划补定】实测 −3.5~−6.5 落在带内；上限 −1 拦住贴顶失真 |
| 同库一致性 | 同一 key 的不同语速档之间，**峰值差 ≤ 3 dB** | 【策划补定·待回填】设计只写"统一响度"，值由本文件定初值，待 `eval/` 首组数据回填 |
| 静音判据 | 阈值取 **−40 dBFS**（16-bit 下 \|s\| > 328 视为有声） | 【策划补定】本文件实测所用口径 |

### 6.1.4 明确推迟

| 项 | 推迟理由 | 落点 |
|---|---|---|
| **响度归一（真 LUFS）** | 设计要求"响度归一（同 LUFS）"，但：① ITU-R BS.1770 的 K 加权滤波标准库里没有，纯 Python 实现属自研组件，不该塞进一张流水线卡；② `say` 本身不提供响度控制，本轮也没有换引擎的打算。本轮**用"峰值带 + 同 key 峰值一致性 ≤3dB"作可测代理**，并在预铸账里**显式标注 `loudness_normalized: false`**，不得让下游误以为已做 LUFS 归一 | 后续卡（引入音频处理链或换引擎时） |
| **多分片资产（`part_index > 0`）** | 资产格式已含 `part_index`，但源格式本轮不引入"一句拆多片"的表达（长话术一律拆 key）。T05 只产 `part_index = 0` | T09 之后按真实长话术需要再开卡 |
| **变体池自动生成** | 设计的"3–5 个变体"是**内容创作要求**，不是流水线能生成的（生成话术属业务侧） | `packs/`（T09 写示例业务包时落实） |
| **失败重试/退避** | 设计未给策略；本轮"失败即入 `failed[]` 并 fail-closed"，不重试 | 若真机出现偶发失败再开卡 |

### 6.1.5 差量重铸【策划补定】

- 复用条件（**四条全中才复用**）：包内存在同 `key`+`part_index`+`rate_key`+`variant` 的条目、
  且该条目的 `fingerprint` 与新源重算的指纹**相同**、且其音频文件**存在**、且 `voice`/`model_version` 与当前引擎一致。
- 任一不中 → 重铸该条。指纹公式只用已冻结的 `assets.fingerprint`（**唯一实现**，不得另写）。
- **可测判据**：同一输入重跑 → TTS 调用次数 = 0；改一个 variant 文本 → TTS 调用次数 = 1（只重铸该条）。

### 6.1.6 失败的处置【策划补定】

- **默认 fail-closed**：任一条目合成失败或质检不过 → **不写包**、抛错，错误里带完整预铸账（含 `failed[]`）。
- 显式 `allow_partial=True` 时才写"部分包"，且预铸账 `clean` 字段必须为 `false` 并把失败原因逐条列出。
- **禁止静默跳过**：任何跳过都要进预铸账。

## 6.2 执行器（runtime / T07）

### 6.2.1 未命中的默认行为【冲突已裁定】

设计稿（`立项案 §4.1`）写"`key` 缺失 → 走未命中分支（云端/本地生成）"；`runtime/AGENTS.md §③` 写"未命中且**未显式开启降级** → 抛错中止"。二者**不冲突**，取并集理解：

- **默认 = fail-closed 抛错**（不播任何东西、不换话术）；
- **显式开启降级**（执行器构造参数 `allow_fallback=True`）才走慢路；
- **降级必留痕**：走降级必产 `fallback` 事件（含 key、原因）。

### 6.2.2 未命中的三种原因必须可区分【策划补定，承接 `00-索引.md` 跨批待办 ③】

`assets.AssetPack.lookup` 按契约一律返回 `None`（它只做判定、不做降级，这是设计决定）。三种语义不同的未命中：

| 情形 | 语义 | 事件 `reason` |
|---|---|---|
| 包内没有该 `(key, part, rate, variant)` 组合 | 没预铸过 / 剧本引用了不存在的枝 | `key_not_prebaked` |
| 有组合但指纹不匹配 | 话术改了没重铸（**过期资产**） | `fingerprint_mismatch` |
| 有组合、指纹匹配但音频文件缺失 | 包损坏 / 同步不全 | `audio_file_missing` |

**执行器必须自行区分并写进事件**（`assets/` 冻结不动）。这三种都不许合并成"未命中"了事——这正是红线要的"本该命中却换了路径必须留痕"。

### 6.2.3 引擎与包的音色/模型版本必须比对【策划补定，承接跨批待办 ④】

调用 `lookup` **之前**，执行器必须比对 `pack.voice/model_version` 与 `adapter.voice/model_version`：

- 不一致 → **不得**静默播包内音频（那是红线举的"突然换了个声音"）；
- 默认按未命中处理（`reason = engine_mismatch`），降级开关打开时走慢路，并留痕。

### 6.2.4 双工参数【策划补定】

设计稿把 `duplex` 放在 plan 对象里，但**冻结的 `core.protocol.parse_plan` 只接受列表**，plan 级 `duplex` 块在协议里没有落点。本轮不为此改内核（改内核须走大版本 + 迁移期）。

**T07 的做法**：双工参数由执行器**构造参数**传入（`DuplexParams`），取值沿用设计稿：

| 参数 | 取值 | 来源 |
|---|---|---|
| `patience_ms` | `400 / 900 / 1800`（快语速 / 默认 / 慢思考） | 【设计原样】立项案 §4.3 |
| `rate_band` | `±15%` | 【设计原样】立项案 §4.3（上游调研写 ±10–15%，取立项案值） |
| `backchannel` | `on` / `off`（本轮只做开关，**不自造"密度"数值**） | 【设计原样】+ 密度档位【明确推迟】 |
| `barge_in` | `allow` / `confirm` | 【设计原样】立项案 §4.3 |
| `silence_pad_ms` | `120–300`，默认 **200** | 【设计原样】`docs/02-protocols-draft §2.3`（上游调研同量级） |
| 槽位前后微停顿 | **50–150 ms**，默认 **80** | 【设计原样】`docs/03-design-notes §3.3`（上游调研 §3.6 同） |

### 6.2.5 槽位处理【冲突已裁定】

`runtime/AGENTS.md §①` 写"槽值**永远现场合成**"；`docs/03-design-notes §3.3` 写"短槽直接拼"。
裁定：**两者说的是不同环节**——"短槽直接拼"指**拼接方式**（槽值音频短，直接接进框架音频，不做重采样/淡入淡出）；
"永远现场合成"指**来源**（槽值一律现场合，不入资产库）。
**T07 一律现场合成**；"长槽整句现场合成、不拼"的**长/短界限数值设计未给** → T07 对槽位一律走"现场合成 + 前后微停顿"，长槽特例【明确推迟】。

### 6.2.6 槽值不得入包【设计原样】

`assets` 层已有 `slots`/`phone`/`user_utterance` 黑名单校验；T07 的验收再加一条运行时断言：槽值只出现在现场合成的音频路径里，包目录内不得出现槽值字符串。

### 6.2.7 T07 还需钉的四件事【策划补定】

① **事件字段一律取自 `core/metrics_spec`**（不得在实现里写字符串字面量）。注意该文件的口径：
- `PART` 是「**同一 turn 内多个 plan 单元的执行顺序（从 1 开始）**」，**不是**资产里的 `part_index`（两者语义不同，别混用）；
- 结果三态的定义（照 `metrics_spec` 注释）：`HIT` = 命中预铸资产；`MISS` = **无对应预铸资产**需走慢路；`FALLBACK` = **原应命中**但因校验/版本/一致性原因被迫走慢路。

② **三态与原因的映射**（本文件裁定，执行器照此产出事件）：

| 情形 | 结果 | `reason` |
|---|---|---|
| key 单元，资产命中且音色/模型版本一致 | `hit` | —（空） |
| key 单元，包内无该 `(key, part, rate, variant)` 组合 | `miss` | `key_not_prebaked` |
| plan 单元是自由文本（`SAY_LIVE`，设计上就没有资产） | `miss` | `say_live_text` |
| 组合存在但指纹不匹配（话术改了没重铸） | `fallback` | `fingerprint_mismatch` |
| 组合存在、指纹匹配，但音频文件缺失 | `fallback` | `audio_file_missing` |
| 包与引擎的 `voice`/`model_version` 不一致 | `fallback` | `engine_mismatch` |

**这三个 `fallback` 原因就是跨批待办 ③ 要的"可区分且留痕"**——不许合并成笼统的"未命中"。

> **三者的可达性说明（2026-09-17 验收 T07 时核定，写下来免得后人误判）**：
> - `key_not_prebaked`、`audio_file_missing`、`engine_mismatch` **在正常路径上可达**（T07 验收时我各构造一例实测过）。
> - `fingerprint_mismatch` 是**防御性分支**：`assets.load_pack` 在装载期已校验「条目文本 ↔ 条目指纹」一致，
>   而执行器重算指纹用的就是同一条目的文本，所以在"装载成功且内存态不被改动"的正常路径上**不会触发**。
>   它真正的作用是兜住**内存态不一致**（有人改了已装载的包对象 / 未来并发场景），T07 的用例以"改内存里的
>   `pack.assets[i].text`"来覆盖该分支。
> - 那么"**话术源改了、包没重铸**"这个真实危险由谁兜？——**在编译期兜**：`compiler` 的差量重铸按指纹判定重铸，
>   `assets.validate_pack` 在装载期拒掉自相矛盾的包。运行时**拿不到话术源**，本就不该由它兜（它只有包）。
> - 若将来编排层要把"当前打算播的文本"传给执行器（例如状态机自己持有话术），`fingerprint_mismatch` 就变成
>   可正常触发的一等路径——那时再加一个 `expected_texts` 入参即可，**协议无需改动**。

③ **`variant="auto"` 的选取规则**（`docs/02-protocols-draft §2.1` 只写了"轮换/随机"，未给算法）：按 `(turn_id, part)` 的**稳定散列**在包内该 key 的可用 variant 里取一个 —— 同一轮次同一单元**可复现**（评测要能重放），跨轮次会变化（落实"防复读机"）。事件里必须记录**实际选中的 variant 值**。

④ **段级淡入淡出**（`runtime/AGENTS.md §③.5` 要求"参数化且可测"）：参数 `fade_ms`，默认 **5 ms**，在每段音频首尾施加线性淡入/淡出（预铸资产与现场合成片段一视同仁）。
数值来源：**【策划补定初值·待回填】**——远小于句边界静音垫（120–300 ms），足以消除拼接残余的不连续；等 `eval/` 的拼接自然度基准出了数据再回填。禁止把它当"已标定值"引用。

## 6.3 本轮明确不改内核

`core/` 保持 **v0.1 冻结**，原因与后果写清楚：

| 缺口 | 不改内核的理由 | 后果与落点 |
|---|---|---|
| R-5 的 `SAY_LIVE` 必须带 `reason` | `PlanUnit` 无此字段；加字段属协议增补，且"必须带"是**规则级**约束，规则语义该由 `compiler/` 的校验器判，不该塞进 wire 格式的解析器 | 该条**暂为人工判**（T06 卡里明确写）；真要做机器判时走 core v0.2 + 迁移 |
| plan 级 `plan_id` / `duplex` 块 | 同上 | T07 以构造参数替代（§6.2.4）；`plan_id` 由调用方随 plan 一并传入 |
| 多分片寻址 | 源格式本轮不表达多片 | T05 只产 `part_index = 0`；T07 仍按 `part_index` 升序探测（兼容未来） |

> **纪律提醒**：任何"协议该有却没有"的字段，都不许在实现里**另起一套隐性约定**——要么按上述方式显式绕开并留档，要么走大版本改内核。
