## 一、约束（评判的先决条件，全部来自本仓既有纪律与实况）

1. **零第三方依赖**是卖点之一（README 徽章级纪律）；任何接入形态不得引入 pip 依赖。
2. **毫秒首音的价值只在链路内兑现**：命中即播 0.7 ms（磁盘读）——多一跳网络、多一次工具往返都会稀释它。
3. **宿主无关纪律**（`AGENTS.md` 纪律 8）：接入外部框架 = 写 `adapters/framework_*` 去适配它，不改内核。
4. **实际运行环境不是 macOS 本地**（用户 2026-09-24 明确）：演示与缺省不得以 `say` 为基调。
5. 冻结区（`cli/` 等）改动须用户开批；扩展区（`adapters/` `packs/` `trigger/`）随便加。

## 二、候选形态（收集一版）

| # | 形态 | 本质 | 适合谁 | 优点 | 代价 |
|---|---|---|---|---|---|
| 1 | **CLI**（现状 `bin/vox`） | 出进程、JSON 输出 + 退出码 | 一切能执行 shell 的 agent / 脚本 / cron | 零依赖、已在、可验证、调试透明 | 每轮一个 Python 进程（数十 ms 启动）；宿主须同机 |
| 2 | **MCP server** | 标准工具协议（JSON-RPC over stdio），长会话 | Claude / ZCode / 自研等一切 MCP 客户端 | agent 生态的宿主无关事实标准；工具 schema 供模型直接消费 | 官方 SDK 是第三方依赖；语音播放不适合走工具往返 |
| 3 | **Skill 技能包** | 说明书 + 脚本 + 素材的目录 | 支持 Skills 的 agent 宿主 | 与 CLI 天然组合；零依赖；可把预铸包随技能分发 | 各家 skill 格式不完全统一；只是知识与分发载体，不是运行时 |
| 4 | **进程内 adapter**（已有 `framework_kefu`；待做 pipecat/livekit） | 宿主进程 import，直接查包播音频 | 语音 agent 框架、业务系统 | **延迟最优（0.x ms 只有这条路能兑现）**；接缝已在 `docs/21` 探明 | 绑 Python 与框架版本；分发要处理 |
| 5 | **独立服务（HTTP/WS）** | 把 runtime 包成常驻服务 | 多 agent 共用资产、远程宿主 | 跨语言、集中部署、资产集中管理 | 自定协议或运维成本；语音内联场景多一跳 |
| 6 | **框架层继续扩** | = 4 的家族化 | 开源语音框架用户 | 每接一个框架多一批用户 | 逐个框架投入，持续但线性 |

**先例**：`adapters/framework_kefu/`（最小侵入、默认关、可摘除）证明形态 4 的通路成立。

## 三、评判一版

**总纲：不单选，按「数据面 / 控制面」分层。**

- **数据面（出音）= 形态 4 + 5**。命中后要"听见"的那条路必须贴着宿主：进程内 adapter（框架/业务系统）
  或本机常驻服务（跨语言宿主）。**MCP/CLI 不进数据面**——工具往返 + 音频回传会把 0.7 ms 稀释成"又一个 TTS"。
- **控制面（决定说什么 / 查什么）= CLI + Skill 先行，MCP 第二**：
  - CLI 是最大公约数，零依赖纪律不破；
  - Skill 是 CLI 的说明书与分发单元，**预铸包 + 使用说明 + 调用脚本打包成技能**是"前置包作为能力"的最自然形态；
  - MCP 覆盖面最大（工具面生态），**以手写最小实现落地**（见 §四）而不是引 SDK。
- **明确不做**：为接入改内核；只服务单一宿主的私有插件；音频传输走工具协议。

**对外交付三件**：`CLI`（人人能用）、`Skill`（装上即会用，可随包分发）、`MCP 薄壳`（agent 生态即插即用）；
**真正兑现毫秒首音的是给框架/业务系统写的进程内适配器**——那是"销售件"，不是"集成件"。

## 五·附：形态 5（独立常驻服务）落地的前置条件

> 定案 3 的展开。**一句话**：形态 5 不是「把现有 `vox run` 包成 HTTP」——
> 现有执行器的形状（单包构造 + 输出必填）**结构上就不支持常驻服务**，改它必动冻结区 `runtime/executor.py`。

**落地前必须先在扩展区具备三件**（三件都在扩展区，与冻结区改动分离）：

| # | 前置件 | 要解决什么 | 落点（扩展区） |
|---|---|---|---|
| 1 | **pack 集合视图** | 现有 `Executor` 是**单包**构造——一次 `__init__` 绑一个 pack。常驻服务要按 key 在多个包间路由，先得有「包集合」这一层 | `adapters/`（如 `adapters/framework_*` 的集合封装） |
| 2 | **音频 sink 注入** | 现有 `execute` 的 `out_path` 是**必填位置参数**，语义是「拼好写盘到本地文件」。常驻服务要的是「把字节交给 sink」（推流 / 回传 / 转发），不是落盘 | `adapters/`（sink 实现） |
| 3 | **pack 缓存** | 进程常驻后不能每次请求都重开包读索引，否则省下的进程启动又被 IO 吃掉 | `adapters/`（或 `packs/` 侧缓存） |

**判定：前两件必然要求改 `runtime/executor.py`（冻结区）。** 代码级依据（可复跑）：

```sh
sed -n '122p;197p' runtime/executor.py
# 122: def __init__(self, pack, adapter, *, duplex: Optional[DuplexParams] = None,   ← 单包构造
# 197: def execute(self, plan, *, plan_id, turn_id, out_path) -> ExecutionResult:    ← out_path 必填
```

第 3 件（缓存）不必然动冻结区，但前两件动 → **形态 5 的成本里含一张冻结区卡**。
因此：形态 5 开工时**必须走冻结区开批流程**（`AGENTS.md` 纪律 9 + 迁移期），
**不能按「扩展区随便加」的预期排期**。这正是本节提前写下来的原因——避免开批时才发现。
